# 1. 项目目的与总体框架

## 1.1 项目目的

本项目面向宏病毒组/宏转录组跨宿主、跨样本类型标准化需求，核心目标是建立一套适用于不同宿主与样本类型的宏转录组标准化操作流程（SOP），提升病原体检测的一致性与可比性。项目需要解决的核心问题不是单次样本能否测出结果，而是不同宿主、不同样本类型、不同建库和 rRNA 去除策略下，如何形成可比较、可审计、可规模化、可推广的共识性方法。

项目处于 X 传染病监测与未知病原体检测的应用背景之下，但**本项目成果不直接纳入国家重大专项任务书交付**；优先路径为高水平方法学论文，再视成熟度推进团体标准或行业指南。现有宏转录组实验流程在组织、粪便、拭子、虫体等样本之间差异很大，核酸完整性、抑制物、宿主背景、rRNA 占比和低输入问题都会影响建库成功率和下游检出。因此，本项目采用“主流程 + 分支流程 + 统一指标框架”的方式推进，并以多团队协作（科研机构统筹设计与质控、试剂方与测序/探针方协同）落地可推广 SOP。

## 1.2 总体目标

项目总体目标包括五类交付：

1. 建立覆盖样本采集、保存、核酸提取、rRNA 去除、RNA 打断/逆转录、建库、测序和生信分析的标准化 SOP（一期以提取后关键环节为主，见第 4 章边界）。
2. 明确组织、粪便、拭子、虫体四类动物源性样本中哪些环节可通用，哪些环节必须分流；**一期暂不包括环境样本**。
3. 建立跨宿主 rRNA 去除与建库策略评价体系，优先比较酶法与探针法（含 LNA、RNase H 等）的去除效率及适用边界，并联动建库效果评价。
4. 建立 XvirBench 统一指标框架，使不同批次数据进入同一 metric_id、manifest、registry 和 harmonized 表体系。
5. 成果路径：**优先发表高水平方法学论文**；后续联合推进团体标准/行业指南（含正在制定的未知病原体检测团体标准），不以国家标准或重大专项任务为近期硬交付。

### 1.2.1 应用范围与一期边界（专家共识）

| 维度 | 一期共识 |
| --- | --- |
| 宿主/样本来源 | 动物源性样本为主（如蝙蝠、啮齿类、蚊虫等） |
| 样本类型 | 组织、粪便、拭子、虫体；建议统一新鲜采集（液氮/干冰），四类样本尽量重新采样以把控变量 |
| 排除样本 | 环境样本暂不纳入 |
| 特殊样本评估 | 重点评估低载量（如血清、脑脊液）与高降解样本；可人为模拟降解以控制变量 |
| 方法学焦点 | 核酸提取**之后**的技术比较：rRNA 去除与文库构建策略 |
| 一期不开展 | 靶向富集、病毒颗粒负极（VLP）、VSP 等复杂前处理；**不做提取试剂品牌/原理横向对比**（变量过多） |
| 提取基准 | 暂以诺唯赞现有试剂盒为统一基准，提取优化留待二期 |
| 文库规模 | 第一阶段目标约 500–1000 个文库（与一期约 750–850 文库口径一致），按小样本筛选 → 验证 → 鲁棒性测试推进 |

## 1.3 项目规模口径

本项目有三个规模层级，不能混淆：

| 层级 | 样本/数据规模 | 作用 |
| --- | --- | --- |
| 现有测试基础 | 3 个测试数据集 | 为项目设计提供前期证据，不等同于最终标准 |
| 一期标准化验证 | 240 份真实样本，约 750–850 个文库（落在 500–1000 文库目标区间） | 用于主流程和分支流程筛选、分层验证和确认性验证；目标约 6 个月内完成第一阶段验证 |
| 长期扩展规划 | 约 1500 份样本（二期及以后） | 用于多宿主扩展、提取方案比较、复杂前处理评估，以及论文补充与团体标准申报支撑 |

## 1.4 标准化路线

项目采用“实验标准化 + 指标标准化”双线并行。实验侧通过分阶段模块化测试收敛流程；一期实验变量优先控制为“高质量 RNA / 降解 RNA”（或优质核酸 / 劣质核酸），避免同时叠加提取品牌、保存液类型等多重变量。数据侧通过 XvirBench 将 W1-W7 输出统一到可比较指标空间。最终形成一套组织和高质量拭子样本可优先采用的主流程，同时保留粪便、虫体/超低输入、高降解/高背景样本的分支流程。时间上力争第一年内（秋季前）完成核心方法学论文撰写。

# 2. 标准化规范体系

## 2.1 样本与元数据规范

所有样本进入实验前必须具备统一登记信息，包括物种、样本类型、采样时间、地点、保存方式、样本重量或体积、冻融次数、前处理方式、提取批次、建库批次、测序批次和分析批次，并登记 RNA 质量分级（高质量 / 降解或 RIN/DV200）。样本编号建议采用全局唯一 ID，同时保留本地样本 ID 和合作方原始编号，避免后续多批次合并时出现重复或错配。

一期样本策略按专家共识执行：优先统一采集新鲜样本并以液氮/干冰保存运输，保留冷链记录；组织、拭子、粪便、虫体四类尽量重新采样，避免混用历史存样引入不可控变量；**不纳入环境样本**。低载量样本（血清、脑脊液等）与高降解样本作为专项评估子集，降解可人为模拟以便对照。样本进入比较实验时采用盲法编号和分层随机，尤其在 rRNA 去除比较中应尽量使用同一样本等量分装的严格配对设计。

## 2.2 实验流程规范

推荐主流程为：

RNA 提取 -> DNase 处理 -> rRNA 去除 -> RNA 打断 -> 逆转录 -> 二链合成 -> 文库构建 -> PE150 测序 -> 统一生信分析。

该主流程优先适用于组织样本和质量较好的拭子样本。分支流程包括：

| 分支 | 适用场景 | 技术要点 |
| --- | --- | --- |
| 粪便分支 | 高抑制、高复杂背景 | 强化去抑制提取，必要时降低去背景强度以减少目标损失 |
| 虫体/超低输入分支 | 单虫、混虫、蜱虫等低输入复杂基质 | 优先保证回收率，减少分装损耗，必要时采用轻打断或不打断 |
| 高降解/高背景分支 | RNA 完整度差或宿主背景异常高 | 避免过度碎片化，保留可建库模板；比较“是否打断”对低质量样本建库的影响 |

一期提取环节统一采用诺唯赞现有试剂盒作为基准流程，不在一期展开多品牌提取对比；主流程与分支流程差异主要体现在 rRNA 去除强度、打断策略和低输入回收策略上。

## 2.3 rRNA 去除与探针策略

rRNA 去除是本项目一期核心比较变量。优先比较酶法与探针法（含 LNA、RNase H 等路线）的去除效率、有效数据提升和对病毒检出的影响；不去除条件作为对照，商业高端试剂盒仅作小规模 benchmark。长期方案不追求“单一探针覆盖全部物种”，而采用类群通用探针池加补丁探针池的策略：脊椎动物通用探针池、节肢动物特异探针池等，并结合 LNA 修饰提高结合稳定性和特异性（探针研发与测序平台侧由华大协同）。

评价标准不应只看 rRNA 残留率，还要联合测序有效数据、建库成功率、病毒检出、微生物谱稳定性、成本和操作复杂度。对于哺乳动物组织可设更严格 rRNA 残留标准；节肢动物因参考序列不足、背景差异大，应更重视相对提升幅度和可推广性。

## 2.4 数据与指标规范

XvirBench 的核心是把不同 workflow 输出映射到统一指标空间。每个批次应至少包含：

| 文件 | 作用 |
| --- | --- |
| samples_registry.tsv / sampleinfo.tsv | 记录 global_sample_id、本地样本 ID、分组、建库方法、run 列表等 |
| manifest.yaml | 记录测序平台、读长、数据库版本、软件版本、各 workflow 输出目录 |
| harmonized 表 | 将 W1-W7 指标按 sample、run、contig、taxon 等粒度统一存储 |
| comparison_config | 描述本批次需要比较的 group、method、sample_type 等变量 |
| W1 QC 报告包 | 内部/交付 HTML、TSV 明细、fig01–fig04 图件（现行交付形态） |

W1-W7 的角色如下：

| Workflow | 标准化含义 | 核心指标 |
| --- | --- | --- |
| W1 | 上游 QC、rRNA 去除、合并和组装 | Q30、fastp 保留率、rRNA 后 reads、contig 数/长度 |
| W2 | 病毒鉴定 | 病毒 contig、CheckV、ANI 聚类 |
| W3 | 宿主鉴定 | 宿主物种、标记基因一致性 |
| W4 | Kraken/Bracken 微生物谱 | 未分类比例、分类 reads、物种丰度 |
| W5 | 病毒定量 | RPM、coverage、mapping rate |
| W6 | 病毒注释 | 注释一致性、参考比对、功能标签 |
| W7 | 建库方法学 benchmark | 宿主比对率、重复率、嵌合率、覆盖偏倚 |

### 2.4.2 W1 上游 QC 分析与交付规范（现行版）

为满足内部评估和客户交付一致性，已固化 W1 五阶段报告规范，并提供可跨平台脚本包与提示词：

| 材料 | 路径 | 用途 |
| --- | --- | --- |
| 复现指南（含完整源码） | `docs/W1_QC_REPORT_GUIDE.md` / `docs/w1_qc_portable/W1_QC_REPORT_GUIDE.md` | 字段口径、评分、图件、运行方式 |
| 报告生成提示词 | `docs/w1_qc_portable/W1_QC_REPORT_PROMPT.md` | 指导在其他平台按同一结构生成 HTML |
| 可移植脚本包 | `docs/w1_qc_portable/`（及 `.tar.gz`） | 拷贝后即可按 `--batch-dir` 复现报告 |

**阶段定义：**

| 阶段 | 名称 | 核心内容 |
| --- | --- | --- |
| S0 | 原始测序 | 样本级汇总 raw reads/bases、Q30、GC |
| S1 | fastp 质控 | 保留率、Q30、重复率、剔除原因分解 |
| S2 | rRNA 去除 | 保留率与 Post-rRNA 深度 |
| S3 | 样本汇总/加测合并 | merge 结果；与 Post-rRNA 一致时以样本级 Post-rRNA 解读 |
| S4 | 组装 | contig 条数、≥1 kb 条数/碱基数、平均长度、≥1 kb 占比 |

**计量与关键口径（必须一致）：**

| 类型 | 规则 |
| --- | --- |
| reads | 统一 **Mb**（÷10⁶），保留 2 位小数 |
| bases | 统一 **Gb**（÷10⁹），保留 2 位小数 |
| 比例 | 统一 **%**，保留 2 位小数 |
| 整数 | 千分位 |
| fastp 保留率 | after / before（分母 = raw） |
| rRNA 保留率 | clean_r1 / fastp_r1（分母 = **fastp 后**，非 raw） |
| 低深度 | Post-rRNA R1 &lt; 5 Mb |
| `contigs_ge1kb_n` | ≥1 kb contig **条数** |
| `contigs_ge1kb_bp` | ≥1 kb contig **总碱基**（Gb） |

**评分（阈值版本 1.0）：** S3 深度 30%、S1 质量 25%、S2 rRNA 15%、S4 组装 30%；映射为优/良/可接受/需关注/不建议下游。批次通过标准为：≥80% 样本达「良」及以上，且「不建议下游」≤10%。

**固定图件（fig01–fig04）：** 各阶段产量、fastp QC、rRNA QC、组装综合（散点/条数/平均长度/≥1 kb 占比）。HTML 图件内嵌，离线可打开。

# 4. 测试方案与验证设计

## 4.1 一期 240 份真实样本设计

一期计划纳入 240 份真实样本（对应约 750–850 / 目标 500–1000 个文库），覆盖组织、粪便、拭子和虫体四类关键技术场景；均为动物源性样本，不含环境样本。样本优先新鲜采集，四类尽量重新采样。

| 样本类型 | 样本数 | 主要研究目的 |
| --- | ---: | --- |
| 组织 | 70 | 建立主流程，比较 rRNA 去除与打断策略（高质量 vs 降解分层） |
| 粪便 | 40 | 在统一提取基准下优化高抑制/高背景的去 rRNA 与建库策略 |
| 拭子 | 70 | 优化低输入回收、打断策略与保存条件适配 |
| 虫体 | 60 | 优化单虫/混虫、低输入和复杂背景的去 rRNA/建库流程 |
| 合计 | 240 | 支撑主流程和分支流程收敛 |

另设专项评估子集：低载量样本（血清、脑脊液等）与人为模拟降解样本，用于检验流程在极端条件下的检出表现，不挤占上述四类主矩阵的核心比较功效。

## 4.2 三阶段实施

| 阶段 | 样本数 | 目标 | 决策输出 |
| --- | ---: | --- | --- |
| 第一阶段：小样本筛选 | 80 | 快速比较 rRNA 去除（酶法 vs 探针法）与打断/逆转录策略；按高质量/降解分层 | 每类样本保留 1–2 套 rRNA 去除方案和打断策略候选 |
| 第二阶段：分层验证 | 136 | 验证主流程和分支流程在不同宿主/样本中的稳定性 | 主流程 SOP 初稿、分支 SOP 初稿、样本分流规则 |
| 第三阶段：鲁棒性测试 | 24 | 评估批次一致性、操作者复现与跨批次稳定性 | 最终 SOP 和标准化输出 |

时间目标：约 6 个月完成第一阶段验证，并支撑年内核心论文撰写。

## 4.3 模块化测试设计与一期排除项

**一期核心变量控制：** 明确实验主变量为“高质量 RNA”与“降解 RNA”（优质核酸 / 劣质核酸）两类，在统一提取基准上比较下游处理差异；避免同时叠加提取试剂品牌、保存液类型、复杂前处理等多重变量。

| 模块 | 一期是否开展 | 内容 |
| --- | --- | --- |
| 模块 A：核酸提取比较 | **否（留待二期）** | 采集方式、保存方式、提取原理及同原理不同试剂盒变量过多，商业试剂盒难以精准控制单一变量；一期统一以诺唯赞现有试剂盒为基准 |
| 模块 B：rRNA 去除比较 | **是（核心）** | 不去除对照、酶法、探针法（LNA / RNase H 等）；商业高端试剂盒仅在第一阶段选 8–12 份代表性样本作 benchmark，不建议全量铺开 |
| 模块 C：打断与建库策略 | **是（核心）** | 用优质核酸验证逆转录前打断顺序的科学依据；比较是否打断对低质量/高降解样本建库效果的影响；保留轻打断或不打断分支候选 |
| 复杂前处理 | **否（一期排除）** | 暂不纳入靶向富集、病毒颗粒负极（VLP）、VSP 等 |

## 4.4 质控与对照

每批实验至少设置提取空白、建库空白、外源 RNA spike-in、Mock 阳性对照和技术重复；并记录 RNA 质量分级以便按高质量/降解分层分析。异常样本包括样本信息不完整、严重腐败污染、材料不足、建库失败、对照异常、同批重复偏差过大等，必须在进入统计分析前完成判定。

# 5. 评价指标与数据分析体系

## 5.1 评价指标

评价体系分为四级：

| 层级 | 指标 | 解释 |
| --- | --- | --- |
| 实验可做性 | 提取成功率、建库成功率、文库浓度、PCR cycle、重复率 | 判断流程能否稳定执行 |
| 背景去除效果 | rRNA 比例、去 rRNA 后 reads、宿主/背景 reads 占比 | 判断去背景是否有效且不过度损失 |
| 病毒检出能力 | 病毒 contig 数、RPM、coverage、阳性样本检出率 | 判断下游核心目标是否提升 |
| 推广性 | 单样本成本、操作耗时、自动化兼容性、批次一致性 | 判断能否用于规模化项目 |

## 5.2 统计分析原则

rRNA 去除模块应优先采用同一样本等分后的配对分析；主流程和分支流程比较应按样本类型和宿主类别分层；方法优选不以单一 p 值为依据，而结合效应量、置信区间、稳定性、成本和可解释性。小样本阶段的统计结论仅作为筛选依据，不能替代第二、第三阶段验证。

## 5.3 XvirBench 比较层与现行分析管线

XvirBench 比较层读取 harmonized 表，不直接修改 workflow 规则。跨批次比较前必须检查数据库版本、软件版本、病毒参考策略和样本分组语义。

现行分析分为两层，职责不同、可并行交付：

| 分析层 | 入口脚本 | 主要输出 | 用途 |
| --- | --- | --- | --- |
| 分组比较层 | `scripts/analysis/run_analysis.py` | `analysis/report.html`、tables/figures | 方法×宿主分层比较、统计检验、全流程联读 |
| W1 上游 QC 交付层 | `scripts/analysis/run_w1_qc_report.py` 或 `docs/w1_qc_portable/run_w1_qc_report.py` | `w1_qc_<host>/report_*.html`、TSV、fig01–fig04 | 内部评估与客户交付的标准化下机-QC-组装报告 |

报告层最低要求：

1. 批次概况与样本/方法分布；
2. QC 面板（深度、Q30、rRNA、组装）；
3. 组间比较与低深度/异常样本标记；
4. 病毒/微生物/宿主指标联动（来自 W2–W7）；
5. 可导出 TSV/Excel 与可离线打开的 HTML。

其他平台若尚无完整 XvirBench 仓库，可直接使用 `docs/w1_qc_portable/`，并按 `W1_QC_REPORT_PROMPT.md` 的章节顺序与摘要模板生成同结构报告；字段缺失时只汇总真实存在字段，不臆造数据。

## 7.3 测试数据集三：鼠组织 rRNA 探针去除与 64 样本综合结果

该数据集对应 dataset3。核心结果来自 24×2 严格配对实验和 64 样本综合报告。24×2 实验采用同一个体、同一组织来源的成对设计，每个个体包含 LNA 探针去除和未去除 rRNA 对照两份文库。

| 指标 | 数值 |
| --- | ---: |
| 配对个体 | 24 |
| 分析文库 | 48 |
| 物种 | 3 |
| 组织类型 | 5 |

关键配对统计：

| 指标 | 单位 | LNA 中位数 | Control 中位数 | 差值中位数 | LNA 较高配对 | P 值 |
| --- | --- | --- | --- | --- | --- | --- |
| 原始 read pairs | M read pairs | 90.32 | 71.1 | 9.56 | 16/24 | 0.1516 |
| Post-rRNA reads | M reads | 106.56 | 13.23 | 92.36 | 24/24 | 0 |

结果解释：LNA 组 raw read pairs 中位数为 90.32 M，对照组为 71.1 M；LNA 组 fastp reads 保留率中位数为 66.4%，对照组为 27.8%；LNA 组 Post-rRNA reads 中位数为 106.56 M，对照组为 13.23 M。该结果支持自合成 LNA 探针在鼠组织样本中显著提高可用于后续分析的数据规模，但同时需要注意 raw Q30 在 LNA 组低于对照组，说明方法优化不能只看去除效率，还要同步评估测序质量和建库稳定性。

源报告还提示一个关键数据治理问题：实验管理表中 Method 与“是否去除 rRNA”字段存在 16 行交叉错位，当前分析应以 Method 作为权威分组字段；提取试剂盒字段缺失，论文或正式交付前需要补录。

三组测试数据对后续项目的支撑关系如下：

| 测试数据集 | 已回答的问题 | 对后续项目的意义 |
| --- | --- | --- |
| 鼠/蚊/蜱打断建库与 XvirBench benchmark | 建库方法差异可否被 W1-W7 指标统一描述；W1 QC 交付报告是否可固化 | 支撑 XvirBench 作为跨批次统一指标框架，并沉淀可复现的 W1 报告规范与脚本包 |

# 8. 风险治理与下一步计划

## 8.1 主要风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 样本质量波动 | 混淆方法差异和样本差异 | 强制登记保存、冻融、输入量、RIN/DV200 等信息 |
| 低输入样本建库失败 | 虫体/拭子样本有效数据不足 | 建立低输入分支流程，减少分装损耗 |
| rRNA 去除效果跨宿主差异大 | 单一方案难以推广 | 使用主流程 + 类群特异补丁探针 |
| 数据库和流程版本不一致 | 跨批次比较失真 | manifest 强制记录数据库、软件和参数版本 |
| 指标口径不统一 | 合作方结果不可比 | 统一 metric_id、单位、粒度和统计口径 |
| 标签或分组字段错位 | 统计结论错误 | 设置权威字段、异常台账和交付前校验 |
| 一期变量叠加过多 | 无法归因方法差异 | 严格按高质量/降解分层；提取与复杂前处理留二期 |
| 混用历史存样 | 引入不可控保存/冻融效应 | 优先新鲜采样与统一冷链；历史样本仅作参考不进入核心对照 |

## 8.2 近期任务与时间节点

1. 冻结一期 240 样本矩阵、RNA 质量分层字段和样本台账；明确新鲜采样与四类重采计划。
2. 完成第一阶段约 80 份样本的小样本筛选（rRNA 去除：酶法 vs 探针法；打断策略；高质量/降解分层），目标约 6 个月内完成第一阶段验证。
3. 将现有三个测试数据集全部整理为 manifest、samples_registry 和 harmonized 指标表。
4. 对 dataset2 和 dataset3 补齐实验批次、试剂盒、输入量、PCR cycle、建库浓度等缺失字段。
5. 统一生成 XvirBench HTML 报告模板和合作方汇报版图表；将 W1 QC 报告规范推广到蚊/蜱及 dataset2/3。
6. 完成第一阶段评审，明确第二阶段保留的主流程和分支流程（提取基准保持诺唯赞）。
7. 建立专项沟通群，落实华大—诺唯赞—科研机构分工；推进团体标准联动与施莽团队数据/文稿参考共享。
8. 视需要补齐 W6 抽取，并保持 `w1_qc_portable` / 提示词与仓库内脚本同步；同步启动核心方法学论文提纲，力争年内秋季前成稿。

## 8.3 最终建议

当前应将三组测试结果定位为“前期测试基础”，不是最终标准结论。项目正式推进时，应以 240 份真实样本、约 500–1000 文库作为一期标准化验证主体；二期再扩展提取比较、环境样本与复杂前处理。汇报时建议强调六点：第一，一期定位是可推广的宏转录组 SOP 与方法学论文，而非重大专项任务交付；第二，应用范围限定动物源性四类样本，不含环境样本；第三，方法学比较聚焦提取后的 rRNA 去除与建库，提取横向对比留二期并以诺唯赞试剂盒为基准；第四，实验主变量控制为高质量 vs 降解核酸，避免多重变量叠加；第五，rRNA 去除与打断策略需联合宿主 QC、病毒定量等证据判断，XvirBench 与 W1 QC 规范构成可比较证据链；第六，协作上华大负责测序/探针、诺唯赞负责提取与去 rRNA 试剂、科研机构统筹设计质控，并联动未知病原体检测团体标准。
