# 宏转录组未知病毒自动鉴定系统研究方案：领域系统、确定性执行与可替换 Agent 编排

**版本**：v0917（2026-09-17）  
**前版**：v0616 / v260830《AI 驱动的 Harness 工程与智能决策框架》  
**配套**：同目录《BioAgent 技术架构》；实施清单沿用三轨 M0–M3（`docs/plan/v260830/bioagent-implementation-roadmap(1).md` 经本版原则修订）  
**定位**：可向疾控机构**私有化交付**的病毒鉴定与专家研判系统，而不是再做一个通用 Agent。

---

## 摘要

本方案在 v260830 实验设计之上做一次**方向修正**：保留「从 FASTQ 到可审计鉴定报告」的目标，但不再把 Claude Agent SDK、Open WebUI 或强化学习调度当作系统本体。竞争力在**本地参考库、版本化知识、鉴定规则、计算插件与窄任务本地模型**；交互界面与会话 Harness 必须可替换。

系统从「固定产线」进化的正确形态，不是「模型自己拼 Snakemake 的协诊专家」，而是：

1. **确定性执行器**：模型只产生 `respond` / `clarify` / `propose_patch`；配对、编译、路由、执行、数值报告由宿主服务完成。
2. **证据研判器**：计算产物解析为候选级证据，规则标记矛盾与缺失，知识提供有出处的条文，主 Agent 只写受校验的说明。
3. **专家监督闭环**：审核修订追加版本，不覆盖原报告；纯解释不重算，新增计算须确认。
4. **可私有化资产包**：参考库、知识、规则、插件、模型分别发版、校验、回滚；默认 `local_only`。

v0616 已完成的双节点拓扑、Open WebUI 演示链路、W1–W6 Snakemake 部署与确定性 runner，作为**工程地基予以保留**。本版明确放弃或降级：模型直接调用 Bash 跑流水线、强制完整思维链写入用户报告、未校准的贝叶斯/GNN 总概率、强化学习调度、把所有专业能力拆成 Subagent。

## 0. 相对 v260830 的修订说明

| 原方案主张 | 本版决定 | 原因 |
| --- | --- | --- |
| Harness（Rule/Skill/Subagent/MCP）为系统骨架 | Harness 是**可替换编排器**；领域逻辑在 catalog / compiler / runner / 知识模块 | 避免绑死 Claude SDK 或某一家 DeepSeek Harness |

| 紧急路径可因 Kraken 门槛结束整条 pipeline | 智能模式：**快报后继续**已确认目标 | 初筛子集不能冒充全量鉴定 |
| GMM / 贝叶斯网络 / GNN 输出后验概率 | 近期用**审核规则 + 支持程度**；无校准数据不承诺概率 | ICTV 标准类群特异，硬统一阈值不成立 |
| 强制完整 Chain-of-Thought 进报告 | 改为结构化决策依据：证据、规则、矛盾、缺失 | 可审计性建立在可复算事实上 |
| DQN 调度、每月自动模型更新 | **不纳入本轮**；先稳定队列、运行历史、专家反馈与回归评测 | 无奖励信号空训 |
| 专家反对自动重跑 | 反馈先成修订或补证提议；补算须确认 | 避免无意义重算 |
| 所有专业能力都拆成 Agent | 查询走检索，算法走工具，融合走主 Agent；subagent 仅当可独立验收 | 减少不可控工具环 |
| 回迁 XvirMind core 的 Rule/Skill 目录 | 实现中心保持 bioagent；规范用契约而非再造一套骨架 | 边开发边搬家风险高 |

## 1. 研究背景与目标

### 1.1 问题域

疾控与科研场景需要在有限时间内完成宏转录组样本的病原鉴定。现有痛点未变，但归因更清楚：

* **多指标矛盾**：高同源低覆盖、阈值附近、EVE / 污染 / 组装残片，使单阈值脚本误判。这是**规则与证据问题**，不是再加一个会聊天的模型就能消失。
* **应急响应僵化**：固定全流程无法同时满足「尽快出快报」和「不要漏检」。需要**确定性路由 + 阶段报告**，而不是模型临时删步骤。
* **黑盒不可追溯**：若结论来自模型自由生成的 HTML 或未引用的文献，专家无法复核，系统也无法从打回中进化。
* **私有化约束**：样本、路径、报告默认不出域；云端大模型只作开发基线或显式授权比较。

### 1.2 研究目标

构建一套**可私有化、可迭代更新、结论可检查**的病毒鉴定系统：

1. **稳定完成分析**：用户确认目标后，计算按注册插件与参考库快照执行；模型不可用时表单路径仍能规划、排队、出数值报告。
2. **专家级综合研判**：将覆盖度、同一性、深度、CheckV、Kraken、定量 RPM 等升维为带冲突/缺失标注的候选评估，并引用本地知识条文；**不是临床诊断**。
3. **应急智能调度**：智能 / 标准 / 紧急三种模式。紧急明确为首期「抽样 + 质控 + 去 rRNA + Kraken」范围；智能模式先出不可变快报，再继续完整目标。
4. **可解释人机互信**：交付包含可复算数值、引用定位、规则命中与审核记录；专家修订追加版本。

### 1.3 范围与约束

* **输入**：配对 PE FASTQ（gzip）或已注册 contig；单样本或多批次。原始文件不修改、不搬动。
* **输出**：业务交付包（HTML 报告 + 证据 JSON + 引用清单）与运行审计包（方案快照、工具/库版本、队列与 attempt）。后处理分析可另出 SCI 风格批次报告（见 XvirBench/benchmark）。
* **非功能**：断点续跑须经验证后新 attempt；多样本并行受磁盘与参考库吞吐约束；版本锁定可重复。耗时目标（紧急快报、标准全流程）在阶段 0 用冻结样本实测后再写入验收配置，本版不预设未验证的小时数。
* **用途**：鉴定与专家研判。不扩展为临床诊断承诺。

### 1.4 部署拓扑

逻辑上三职责，物理上可同机或拆开（开发实例为 cyclone 交互 + 195.66 计算）：

```text
┌──────────────────────────────────────────────────────────────┐
│  交互与业务服务（可替换前端）                                  │
│  浏览器 → 业务后端：项目/权限、上传、确认、报告版本、审核     │
└────────────────────────────┬─────────────────────────────────┘
                             │ 已鉴权的分析 API
                             ▼
┌──────────────────────────────────────────────────────────────┐
│  宿主编排服务（BioAgent，领域逻辑不进 SDK）                     │
│  动作契约 · 检索/规则 · 方案编译 · provider 调用 · 任务提交    │
│  Provider：Claude SDK / 本地 OpenAI 兼容 / 按需 DeepSeek Harness│
└────────────────────────────┬─────────────────────────────────┘
                             │ 已编译 execution_spec
                             ▼
┌──────────────────────────────────────────────────────────────┐
│  计算服务（SSH worker + 私有 tmux + 注册插件）                  │
│  Workflows W1–W6（及后续插件）+ 参考库快照 + Snakemake         │
└──────────────────────────────────────────────────────────────┘

资产平面（与三次运行事实分开写入）：
  知识 release / 规则包 / 参考库目录 / 模型包 / CapabilityManifest
```

三类事实通过 ID 关联，模型不得合并写入：计算以 run state 与产物为准；业务确认与审核以业务库为准；知识以不可变 release 为准。

## 2. 核心设计

### 2.1 专家级综合研判：从「查表投票」到「证据 + 规则 + 受校验说明」

#### 2.1.1 当前瓶颈

单阈值脚本无法处理真实矛盾；大模型直接写结论则会编造数字或文献。正确拆分：

* **观测**必须从产物复算（schema 化 CandidateEvidence）。
* **适用规则**必须版本化，且类群特异（ICTV Code 强调不能用统一数值代替各科标准）。
* **自然语言说明**由主 Agent 生成，但必须通过数值/引用校验才能进报告。

#### 2.1.2 六步融合（替代原「推理引擎一次算后验」）

1. 解析产物为候选与样本级证据（指标定义、单位、分母、来源定位、工具/库版本）。
2. 规则检查：冲突、阈值附近、缺失对照、分节段不完整、EVE/污染/组装提示。
3. 知识检索：只返回已发布 citation_id + locator + 原文片段。
4. 主 Agent 生成结构化 Assessment 草稿（支持/反对/冲突/缺失/建议）。
5. 宿主校验：模型不得新增观测、不得删除冲突、不得自填 verified。
6. 模板渲染报告；不足时只发可验证数值 + 「未生成研判」。

首期**不**部署 GMM/贝叶斯/GNN 总概率。支持程度用有限枚举（充分支持 / 部分支持 / 不足 / 冲突），供专家审核，不当作校准概率。

#### 2.1.3 与系统集成

| 原 Harness 落点 | 本版落点 |
| --- | --- |
| `rules/06_reasoning_rules.md` | 版本化规则包（随 KnowledgeRelease / RuleRelease） |
| `verify_reasoning.sh` | 证据校验器 + 报告模板门禁（无 JSON/绝对路径/未引用 ID） |
| `review_agent` 自由推理 | 主 Agent 仅 task_kind=证据说明，schema 固定 |

后处理批次报告（质控箱线、物种组成、绑图生物学讨论）由 **XvirBench/benchmark 全流程分析体系**承担，与单次鉴定交付包互补：前者面向方法学与队列比较，后者面向单个 run 的候选研判。

### 2.2 应急智能调度：从「弹性指挥中心」到「确定性路由 + 阶段报告」

#### 2.2.1 三种模式

* **紧急 emergency**：首期范围固定为 5% 抽样 + 质控 + 去 rRNA + Kraken2；配对 reads 不可用则拒绝。产出不可变 preliminary 报告。
* **标准 standard**：执行用户确认目标的依赖闭包（W1–W4±W6 等注册能力）。
* **智能 auto**：先做初筛并出快报，**然后继续**已确认目标。Kraken 门槛只作提示，不得把剩余步骤标为 skipped。

抽样比例、种子、过滤过程、Kraken 库版本写入审计包。5% 与物种级门槛仅为**待验证基线**，不是生物学真理。

#### 2.2.2 资源与恢复（替代 RL）

* 单一调度者 + 持久化优先级队列；flock 只作最终互斥。
* 排序：项目优先级 × 项目内紧急级 × 入队时间；可配置等待提升，避免饥饿。
* 运行中 Snakemake job **不抢占**。
* SSH 断线 ≠ 失败；重连核对 state / tmux / PID / boot ID。
* 中断后显式恢复：校验输入、方案、插件、软件、参考库后新 attempt；条件变了则新 plan/run。

历史耗时用于额度估算（P50/P90），不训练 DQN。调度日志入库，为将来可能的学习保留数据，本轮不上线强化学习。

### 2.3 可解释人机互信：从「思维链展示」到「可复核交付包」

用户报告展示：

* 用了哪些证据（含分母与来源哈希）
* 适用哪些规则（rule_id + 版本）
* 存在何种矛盾与缺失
* 引用哪些已发布知识（citation_id + 原文定位）
* 专家审核状态与被替代版本

不把模型内部逐步草稿原样倾倒给用户。内部技术报告（管理员）可保留对话时间线、plan revision、命令版本。

专家交互：

* 认可 / 需补证 / 要求修订；反对必须写结构化理由。
* 纯解释修订 → 新报告版本，不重算。
* 新增计算 → 展示影响范围，确认后新方案。
* 修订导出为微调候选，**不能直接自动训练、不能自动改线上规则**。

## 3. 系统架构与模块集成

### 3.1 四层业务流程（替代原八层 Harness 全景）

原 Layer 1–8（SPEC / Rule / Skill / Subagent / Workflow / Scripts / MCP / dev-map）映射为可运行的四层，避免「层数 = 进程数」：

| 业务层 | 职责 | 主要模块 |
| --- | --- | --- |
| 输入层 | 选文件或上传、配对、预检、样本元信息、项目授权 | WebUI analysis datasets、指纹、groupinfo |
| 方案层 | 目标与模式、受控参数预设、依赖闭包编译、用户确认 | `deterministic_planner`、`pipeline_spec`、`conversation_contract` |
| 计算层 | 队列、worker、注册插件、Snakemake、产物 | `analysis_runner`、`workflow_adapters`、Workflows |
| 交付层 | 数值报告、候选研判、知识引用、专家审核、后处理分析 | `report_evidence`、知识模块、XvirBench/benchmark |

横切支撑：**知识与证据平面**（检索、规则、引用校验）、**资产平面**（库/插件/模型 release）。

原 Harness 概念的新位置：

| 原概念 | 现位置 |
| --- | --- |
| Rule | 规则包 + 编译期参数 schema |
| Skill | 方法技能卡（只读，进入知识检索，不执行 shell） |
| Subagent | 默认不用；专项 SpecialistTask 条件接入 |
| Workflow | CapabilityManifest + Snakemake 插件 |
| Scripts 门禁 | 契约测试、证据校验、发布回归 |
| MCP | 知识/专项发现与查询；**不**作为跑 Snakemake 的必需形式 |
| dev-map 记忆 | 业务库事件 + 不可变报告版本，而不是可改 Markdown 日志 |

### 3.2 一次分析如何完成

```text
选择或上传 FASTQ/contig
  → 确定性配对与预检（失败则停在明确状态）
  → 用户确认样本关系与目标、模式
  → 编译 execution_spec（绑定插件 + 参考库 + 规则版本）
  → 用户确认方案（模型提议必须重新编译，旧方案不就地改写）
  → 入队执行
       ├─ 紧急 / 智能：先出 preliminary 报告（与 execution status 分离）
       └─ 继续完整目标（智能/标准）
  → 解析产物 → 规则 → 检索 →（可选）主 Agent 说明 → 校验 → 模板报告
  → 专家审核 / 补证
  →（可选）批次级 FULL_PIPELINE 分析报告
```

模型在整条链上只出现在：追问澄清、受控改参建议、带引用问答、证据说明。启动计算的按钮属于业务后端。

### 3.3 与现有 Snakemake 流水线的对接

对接方式从「MCP 让 Agent 触发 snakemake」改为「计算节点只跑已注册 adapter」。Agent 节点不持有整库、不写 Snakefile。

#### 3.3.1 数据预处理（W1）

* 部署：`Workflows/workflow1_upstream`（质控、去 rRNA、合并、组装）。
* 注意：去 rRNA、宿主序列去除、宿主识别是三种能力，不得混用。
* Agent：typed adapter 已存在；端到端验收与库快照仍需按插件发布补齐。

#### 3.3.2 病毒鉴定（W2）

* 部署：`workflow2_virusid`（主链默认；2026db 变体须在方案中显式冻结）。
* 后续：NT/NR 进入参考库目录，禁止用目录名猜测版本。

#### 3.3.3 宿主鉴定（W3）

* 部署：`workflow3_hostid`。后续：BOLD 等标记库版本化。

#### 3.3.4 微生物分类（W4）

* 部署：`workflow4_kraken_bracken`。初筛依赖 Kraken，但全库分析与 5% 抽样必须在报告中标明口径。
* MetaPhlAn（W8）是否引入、如何与 Kraken 综合，仍单独立项，不默认进主链。

#### 3.3.5 病毒定量（W5）

* 部署：`workflow5_virus_quantification`。须进入候选证据（RPM 分母=clean reads，低深度单独标注）。

#### 3.3.6 病毒注释（W6）

* 路径：CheckV 过滤 → VIGOR 或 Prodigal-meta → DRAM-v → 一致性与 GenBank。
* 优先作为注册插件，而不是「注释 Agent」。AI 扫描暗物质仅在有独立评测收益时作为专项，不得替代 CheckV/注释流程。

#### 3.3.7 基因组补齐（W9）

* 开发中，不进本版主鉴定链；接入时走同一 CapabilityManifest。

#### 3.3.8 建库方法学（W7）与后处理分析

* W7 为 RNA vs cDNA 打断对照，不替代上游质控。
* 批次指标提取、统计、SCI 图与绑图生物学讨论：`XvirBench/benchmark` 全流程分析体系（提示词 `FULL_PIPELINE_ANALYSIS_SYSTEM.md`）。鉴定 Agent 不重复实现 ggplot 报告引擎。

### 3.4 与外部专业能力的对接

原则：**查询 ≠ 计算 ≠ 融合**。

| 需求 | 默认实现 | 何时才用 Agent/MCP 计算 |
| --- | --- | --- |
| ICTV 条目、科级标准、标志基因 | 本地知识检索 | 只读 MCP 知识源可选 |
| 按科计算 identity / 距离并对照阈值 | 注册 capability | 有可验收输出再接入 |
| 多证据融合 | 宿主六步 + 主 Agent 说明 | 首期不新增融合 subagent |
| 病毒注释 | W6 插件 | 新服务必须证明增量 |
| 风险评估 | 不进本版主链 | 避免「风险暗物质」空转承诺 |

#### 3.4.1 ICTV 分类能力

痛点仍在：标准分散、计算不统一、最近邻放置 ≠ 官方标准。本版路径：

1. 把官方标准结构化进分类知识资产（实体、关系、原文定位、适用范围）。
2. 科级查询走检索，不把 32 科文档塞进 prompt。
3. 真正「按该科基因和阈值计算」做成注册工具，输入 FASTA/候选，输出带公式与版本的证据。
4. TaxonAgent 现状（仅 `ictv_family_info`、本机常关）视为过渡适配器，不能称为已完成官方分类系统。

#### 3.4.2 病毒注释与风险评估

保持为**展望**：先把 W6 跑稳并进入证据图。AI 发现 + 传统验证的叙事可以保留为研究问题，但不作为 M1 交付。结构预测同理。

### 3.5 Agent 模块技术实现：Provider 之后的窄任务模型

#### 3.5.1 技术选型（相对 v260830 的关键变化）

不再规定「统一采用 claude-agent-sdk 作为底层框架」。改为：

* **领域宿主**自有：动作契约、编译器、检索、规则、执行提交。
* **Provider 适配器**封装：Claude Agent SDK（当前 MiniMax-M3 开发路径）、本地 vLLM / llama.cpp / OpenAI 兼容、按需 DeepSeek Harness。
* 切换 provider **不得改变** catalog / compiler / runner。
* DeepSeek Harness 若接入：只使用其结构化生成能力，关闭能绕过宿主审批的自主工具环。

四类本地模型任务：

1. 意图识别与追问  
2. 受控参数建议（preset_id 或白名单字段）  
3. 带引用的知识问答  
4. 候选证据说明  

失败：停在明确状态，转表单或专家；**不自动回云端**，不无限修 JSON。

## 4. 研究内容与关键技术

### 4.1 多证据融合（规则优先）

* **输入**：CandidateEvidence（Kraken、BLAST/Diamond、覆盖、CheckV、RPM、宿主标记等），每项含口径与来源。
* **方法**：类群特异规则命中 + 强制保留冲突；主 Agent 生成自然语言说明。
* **输出**：Assessment（分类归属、支持程度、冲突、缺失、引用、限制）。
* **验证**：冻结困难样本（阈值附近、分节段、对照缺失）；评估冲突是否被隐藏、引用是否可定位，而不是过早报一个总 F1。

### 4.2 自适应调度（规则 + 队列，学习后置）

* **状态**：模式、初筛摘要、资源快照、队列位置。
* **动作**：emergency / auto+continue / standard；waiting_resources；拒绝非法紧急输入。
* **数据**：每次路由写入特征、动作、耗时、专家是否改道。
* **本轮不做**：DQN 上线、每周自动更新策略。

### 4.3 结构化说明生成与校验

* Provider 按 schema 输出 JSON。
* 校验器核：数值 ⊆ 证据包、citation_id ⊆ 本次检索、不得删除规则命中的冲突。
* 专家打回记录错误类型，进入 FineTuneDataset 候选，而不是直接改 system prompt 当生产发布。

### 4.4 人机互信与资产发布

* ReviewEvent 追加，保留期限按项目配置（不写死「两年即可」）。
* 知识：导入 → 许可/哈希 → 结构化 → 审核 → 索引 → 回归 → 发布。
* 参考库：清单 + 哈希 + 兼容矩阵；执行前核清单而非每次全盘扫描 NT/NR。
* 微调：离线训练 ≠ 上线；按任务切换模型包。

### 4.5 计算后标准化分析（新增研究内容）

将「工作流跑完之后」的提取、统计、作图、生物学讨论标准化，使其他平台可复用同一契约：`extract_all(result_dir) -> tables`，报告绑图、缺失跳过、HTML/PDF 同源。这是方法学与队列质控能力，服务于建库比较和流程验收，与单样本鉴定报告分层。

## 5. 实施计划与里程碑

取消原「阶段 1 必须上 RL、阶段 3 自优化闭环」的串行幻想。改为**三条并行轨**与共同验收节点。日期不预设；未测指标不写进完成标志。

| 节点 | 业务闭环轨 A | 领域资产轨 B | 模型替换轨 C | 完成标志 |
| --- | --- | --- | --- | --- |
| **M0** 基线与 demo | 复用结果读取 | 小知识/规则/证据包 | provider + 一种本地后端 | 离线：结果→规则/检索→说明→校验→报告 |

## 6. 验证指标与评估方法

指标必须**分项统计**，禁止合成一个不可解释的总分。下表为目标类型；具体门槛在 S0 用冻结集写入评测配置。

| 类别 | 指标 | 测量方法 | 备注 |
| --- | --- | --- | --- |
| 数值正确 | 报告数字与产物复算一致 | 证据校验器 | 必须 100% 作为门禁 |
| 执行契约 | 非法动作、越权路径、伪造引用拦截率 | conversation_actions 负向集 | 必须全拦截 |
| 引用 | 定位正确率、语义适用（专家） | 检索回归 + 审核 | 定位≠语义充分 |
| 冲突保留 | 已知矛盾是否出现在报告 | 困难样本集 | 隐藏冲突视为失败 |
| 路由 | 紧急范围是否被越权扩大 | 路由回归 | 快报≠全流程完成 |
| 分类质量 | 已知病毒 / 新种 / 阴性 | 仅在有真值的冻结集上报告 | 无真值只评提示行为 |
| 耗时 | 快报 / 全流程墙钟 | 登记 run + 资源档案 | 现场验收前不承诺 |
| 审核成本 | 每份报告专家修订次数与时间 | ReviewEvent | 用于 C 轨，不用于吹嘘「替代专家」 |
| 私有化 | 断网可跑、更新可回滚 | M3 演练 | 开发机成功不等于交付 |

原「准确率 ≥95%、F1≥0.85、假阳性 ≥99%、专家接受率 ≥90%」**降级为待验证假说**，在未冻结金标准前不得作为系统验收条款。

## 8. 预期成果与创新点

### 8.1 预期成果

1. **可安装的领域系统**：交互/编排/计算可配置；W1–W6 以插件注册。
2. **两套报告**：单 run 鉴定交付包（证据+引用+审核）；批次后处理分析包（统计图+绑图讨论）。
3. **资产包**：知识、规则、参考库、模型、插件的发版与回滚演练记录。
4. **评测集**：契约负向用例、困难生物学样本、四类模型任务留出集。
5. **文档**：本方案、技术架构、实施清单、部署手册。

### 8.2 亮点（修订后）

* 把执行权从模型收回，使本地小模型只做窄任务成为可能。
* 用候选级证据和类群特异规则处理矛盾，而不是统一硬阈值或未校准总概率。
* 三种模式 + 阶段报告，应急与完整鉴定不再互相冒充。
* 知识与参考库作为一等产品，支撑断网私有化。
* 计算后分析标准化，便于其他平台复用同一提取-报告契约。
* 数据兼容：二代 PE 为主；插件机制允许后续长读长，而不改宿主契约。
