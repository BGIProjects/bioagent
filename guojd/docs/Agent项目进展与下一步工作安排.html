2. 总体规划回顾

研究方案将系统从「固定产线」升级为「AI 协诊专家」，嵌入三项核心能力：

核心能力计划中的落地形态对应阶段
专家级综合研判矛盾检测、阈值边界引擎、EVE/嵌合体陷阱库、四层结论（确证/高置信/可疑/排除）阶段 1
应急智能调度Kraken2 5% 初筛后选路径 A/B/C；后续用 RL 自优化阶段 1 → 阶段 3
可解释人机互信带证据引用的诊断意见书、专家打回、pitfall_log、持续进化阶段 2 → 阶段 3

计划中的数据流：

FASTQ → W1 质控组装 → W2 病毒鉴定 → W3 宿主 → W4 Kraken/Bracken → W5 定量 → W6 注释 → evidence.json → AI 推理（矛盾 / 阈值 / 陷阱） → 诊断意见书 → 专家审查 / 打回 → 反馈进化

4. 已完成能力清单

4.1 运行时与会话

  • Adapter 只做 OpenAI 协议 / SSE；/plan、/execute 由 adapter 拦截，不污染对话。
  • SessionManager：chat UUID ↔ Claude session，常驻 client + 会话锁；单 worker 部署假设仍成立。
  • plan 模式 dontAsk + 内部 analysis_plan 控制块；execute 模式 bypassPermissions + 注入 runner 命令。
  • 修复：IME 误提交、新对话并行 title-generation 抢 client、跨 assistant 回合 Markdown 边界。

4.2 确定性分析执行（相对旧版最大进展）

  • 类型化 execution_spec：支持 workflow1（任意连续区段）与 virus_classification（reads 或 contigs）。
  • workflow1 线性 DAG：fastp → bowtie2 → merge → megahit → rename_filter，可从中途入口用 symlink 物化前置产物。
  • 病毒分类：固定 workflow2_virusid_2026db；reads 走上游+分类两 phase，contigs 只走分类；UI 线性五段，不暴露并行 DAG。
  • 固定 runner：Snakemake 9.23.1、8 核、--printshellcmds、--benchmark-extended；phase 失败即停。
  • state v3 / telemetry v3：job 级时间与资源、命令与版本、manifest、序列指标；失败/取消不提供交付报告。
  • 已修复真实故障：空 HMM 命中导致 pandas EmptyDataError、子进程找不到 seqkit、benchmark "NA"、agent 未预置 workflow 导致找不到 smk。

4.3 自适应路由（阶段 1 的规则基线）

  • adapter adaptive_virus_analysis：先 adaptive_screen 再 adaptive_route。
  • 初筛：配对 FASTQ 校验、5% 抽样、Kraken 报告解析、物种级病毒 clade 统计。
  • 高置信已知病毒门槛（同时满足）：top species reads ≥ 1000、样本占比 ≥ 1%、占病毒 reads ≥ 80%。
  • 路由模式：auto / emergency / standard / deep；emergency 默认 15 分钟截止；结合 CPU/内存/已分配线程做准入。
  • 这是计划中「路径 A 紧急 / B 标准 / C 深度」的工程雏形，尚未接 RL，也尚未覆盖 W3–W6 全链路。

4.4 报告与 UI

  • 交付报告由后端渲染，不采用模型 HTML（直接针对评测中发现的数字自相矛盾 F001）。
  • W1 报告：摘要、范围、输入、S0–S4、SVG 图、产物清单、科研用途声明；缺测显示「未产生」。
  • W2 报告：候选数、聚类代表、脊椎动物候选、代表性 contig 证据、CSV/XLSX/FASTA；无候选明确写未检出。
  • 分析页资源卡片：P50/P90/建议预留、可信度、匹配 run 数；资源不足不阻断合法方案启动。

4.5 验证规模

  • Agent 单元测试约 80 项（adapter、runtime、runner、workflow、资源校准、自适应路由）。
  • Open WebUI 后端相关测试约 33 项，前端 Vitest 11 项。
  • 真实恢复 run 已成功（如 analysis-20260728-120606-9453ee29：5.54M reads，fastp 保留 77.41%）。
  • workflow2 dry-run 解析 21 jobs；零命中 DNA HMM 通道与 seqkit PATH 问题已用真实失败 run 复现并修好。

5. 与总体规划的主要差距

当前系统更接近「可审计的固定生信执行器 + 规则调度」，尚未达到方案中的「多证据融合研判专家」。这不是倒退：把执行从模型手里收回，是后续做可信推理的前提。
差距计划要求现状影响
部署不同步 cyclone 为交互层运行态 最新代码在 liufangzhou，/data/bioagent/agent 仍是旧三文件结构 评测与演示可能测到旧行为
流程覆盖 W1–W6 端到端 + evidence 汇聚 Agent 只接 W1、W2；W3–W6 仅 Snakemake 源码可用 无法做完整鉴定报告
研判内核 矛盾 / 阈值 / 陷阱 / 四层结论 报告只陈述流程客观指标 阶段 1 核心未开始
调度智能化 规则 + RL，紧急 ≤25 min 仅规则 + 资源快照；无历史 reward、无 MCP 调度工具 可做基线，不能宣称自优化
TaxonAgent 按科动态选基因/阈值做分类判定 只查科级知识，不跑计算流程 W6 病毒分类任务无法端到端
人机闭环 打回、结构化反馈、每月 prompt 进化 无 阶段 2–3 未启动
Harness 回接 规范迁入 XvirMind core（Rule/Skill/SubAgent/MCP） 逻辑仍在 bioagent 仓；未按 3.5.2 骨架回迁 双仓并行，规范与实现易分叉

6. 下一步工作安排

建议按「先可部署、再接全流程、再补研判」推进，避免在旧 cyclone 代码上继续堆功能。

P0　工程收口（1–2 周）

任务交付物验收
将 liufangzhou 最新 agent / open-webui 同步到 cyclone /data/bioagent systemd 服务跑新 runner；环境变量与 run root 对齐 同一对话可完成 W1 区段与 W2 分类，并下载确定性报告
TaxonAgent MCP 守护化 5090 systemd；健康检查；调用缓存 adapter 启动后 ICTV 查询不再依赖人工 ssh
自适应路由端到端实测 emergency / standard / deep 各 1 个真实或模拟样本记录 初筛日志、路由理由、后续 phase 与方案一致
Dashboard / System Status 接真实数据 samples / runs / 高风险占位改读 run 索引 不再展示纯静态数字

P1　流程覆盖（2–4 周）

任务交付物验收
为 workflow3 / 4 / 5 / 6 增加 typed adapter（优先 W4，因调度已依赖 Kraken） workflow_adapters.py registry 扩展；UI 线性步骤与 targets 各流程至少 1 次真实或 dry-run 成功，telemetry v3 可解析
定义并写出 evidence.json 汇聚规范 字段：覆盖度、同一性、Kraken 置信、CheckV、定量 RPM、注释摘要 W2（及后续 W5/W6）成功 run 自动落盘，供研判模块消费
明确跨节点策略 继续本机 Bash runner，或实现方案中的 MCP/SSH 桥接到 195.66 文档与代码一致，避免第三套执行路径

P2　阶段 1 研判内核（4–6 周，与 P1 可部分并行）

任务交付物验收
矛盾检测器 + 阈值边界标注（先规则，后概率模型） reasoning_engine：高同源低覆盖、高深度低一致性、近阈值 在模拟 D5/D7 类案例上召回可统计
四层结论生成器 确证 / 高置信 / 可疑 / 排除 + 证据权重；写入报告模板 报告从「流程指标说明书」升级为「鉴定结论」
EVE / 嵌合体最小陷阱库 黑名单 + CheckV 结果门控 已知 EVE 样例不报成确证感染
TaxonAgent 从「查科」扩展到「按科计算并判定」 至少 1 个模式科（如 RdRp 氨基酸阈值）跑通工具链 输出科/属/种、阈值引用、新种标记

P3　阶段 2–3 人机闭环（在 P2 有结论输出之后）

任务交付物验收
专家打回 UI + feedback_collector 结构化理由、样本 ID、AI 结论、专家结论 打回可触发重跑或方案修订，日志不可改
推理链验证脚本 结论均有 ≥2 条证据引用，且能对上 evidence.json 对应研究方案 verify_reasoning.sh
调度日志入库（为日后 RL 做数据） 每次路由的特征、动作、耗时、专家是否改道 先积累 ≥100 条，再考虑 DQN；当前继续规则调度

明确暂缓

  • RL 调度器：等 P0/P1 数据与路由日志稳定后再做，避免无奖励信号空训。
  • 注释 Agent / 风险评估 Agent：W6 生信流程先经 adapter 跑稳，再决定子 Agent 还是流程增强。
  • 生产本地化模型：开发期维持 MiniMax；合规节点单独立项。
  • Harness 整仓回迁 XvirMind core：先冻结 bioagent 为唯一实现仓，回迁作为独立工程任务，避免边开发边搬家。
建议的近期主路径：同步部署 → 自适应路由实测 → W3–W6 adapter → evidence.json → 规则研判与四层结论。评测侧应跟着这条路径升级（见配套报告《Agent 评测 Benchmark 进展与下一步工作安排》），否则会继续用旧 agent 行为打新 rubric。
