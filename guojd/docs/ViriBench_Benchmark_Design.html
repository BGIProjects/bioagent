1. 设计背景与动机

1.1 系统概况

XvirMind 是一套融合AI前瞻性能力的宏转录组未知病毒自动鉴定系统，基于Harness工程化架构（Rule / Skill / Sub Agent / Workflow / MCP / Scripts / dev-map），将三大核心AI能力嵌入系统：

  • 专家级综合研判：多证据融合推理器，处理高同源低覆盖、阈值边界、EVE整合等生物学陷阱
  • 应急智能调度：基于样本特征、资源状态、紧急度的自适应路由（快速通道 vs 完整链路）
  • 可解释推理链：输出带完整推理步骤与证据引用的"诊断意见书"，支持专家审查与持续进化

系统的完整数据流为：

FASTQ (PE150) → 质控/去宿主 (W1) → 病毒鉴定 (W2) → 宿主鉴定 (W3) → Kraken2/Bracken 初筛 (W4) → 病毒定量 (W5) → 病毒注释 (W6) → 证据汇聚 evidence.json → AI 推理引擎 (矛盾检测 + 阈值处理 + 陷阱库) → 诊断意见书 (Markdown + PDF + JSON) → 专家审查 / 打回 → 反馈收集 → 模型进化

1.2 为什么需要专用 Benchmark

现有生信AI benchmark（LifeSciBench、GeneBench-Pro、BioAgent Bench）各有侧重，但均未覆盖以下XvirMind的核心评估需求：

现有Benchmark的局限XvirMind 的特殊评估需求
LifeSciBench 关注单轮科学推理，不涉及多步骤流水线执行需要评估从 FASTQ 到报告的完整端到端流程
GeneBench-Pro 关注统计学推理决策，不涉及实时调度需要评估自适应调度（紧急/标准/深度路径选择）
BioAgent Bench 关注pipeline完成度，不评估推理链质量需要评估"诊断意见书"的推理链完整性与可解释性
三者均不涉及病毒学特有的生物学陷阱（EVE、嵌合体、阈值边界）需要专门评估矛盾检测与生物学陷阱处理能力
三者均不涉及人机协作闭环需要评估专家反馈收集与模型自优化效果

2. 参考文献方法论提取

LifeSciBench (OpenAI, 2026)

核心方法：750个专家编写任务，7个工作流 × 7个生物领域，每个任务配备专家撰写的评分量表（rubric），共19,020条评分标准。

  • 评估方式：单轮，模型接收prompt+附件，产出一份回答
  • 评分：归一化rubric分数 + 任务通过率（≥70%阈值）
  • Rubric设计原则：Specificity、Atomicity、Evaluability、Grounding、Non-redundancy、Operational usefulness
  • 验证：453名独立专家审查，97%拥有博士学位，平均12年经验
ViriBench 借鉴：专家rubric评分体系，用于评估"诊断意见书"质量；多维度×多领域交叉分类法

GeneBench-Pro (OpenAI, 2026)

核心方法：129个多阶段统计分析问题，10个领域 × 21个子领域，每个问题3-13个决策点。

  • 数据策略：完全模拟数据，已知ground truth，精确控制复杂度
  • 设计原则：唯一可识别答案、清晰数值分离、消融支持、最小可行prompt
  • 评分：二元通过/失败，带校准容差
  • 关键概念："decision cascade"——上游错误选择传播至下游失败
  • 验证：11名外部专家审查82个问题
ViriBench 借鉴：模拟数据集构建策略（已知ground truth）、decision cascade设计、消融验证、二元通过/失败评分

BioAgent Bench (Entropic / FER, 2026)

核心方法：10个端到端生物信息学任务（含viral metagenomics），评估AI agent在真实pipeline中的表现。

  • 评估方式：agent在沙箱中执行完整pipeline，指定输出格式（CSV/TSV）
  • 评分：LLM grader（GPT-5.1）打分，输出 steps_completed / steps_to_completion / final_result_reached / f1_score
  • 鲁棒性测试：三类扰动——corrupted inputs、decoy files、prompt bloat
  • 稳定性测试：多次试验，Jaccard Index（分类数据）+ Pearson相关（数值数据）
  • 关键发现：高完成率不等于可靠——pipeline能完成不代表步骤级推理正确
ViriBench 借鉴：端到端pipeline评估、LLM grader机制、三类鲁棒性扰动设计、多次试验稳定性指标

3. Benchmark 总体架构

ViriBench 采用六层评估架构，从底向上逐层递进，每层聚焦不同的评估目标，对应系统不同的AI能力模块：

Layer 1 流水线完成度评估 (Pipeline Completion)

评估目标：系统是否能端到端完成从 FASTQ 到结构化报告的全流程

对应系统模块：Snakemake workflows 1-6 + MCP桥接层

方法：参考 BioAgent Bench —— LLM grader + 指定输出格式 + 步骤完成率

Layer 2 AI推理准确性评估 (Reasoning Accuracy)

评估目标：多证据融合推理器是否能正确处理矛盾、阈值边界、生物学陷阱

对应系统模块：review_agent + 矛盾检测器 + 阈值边界引擎

方法：参考 GeneBench-Pro —— 模拟数据集 + 已知ground truth + 二元评分 + 消融验证

Layer 3 调度智能评估 (Scheduling Intelligence)

评估目标：自适应调度器是否能根据样本特征与紧急度选择正确分析路径

对应系统模块：PMAgent + adaptive_scheduler + MCP pipeline_scheduler

方法：路径选择正确率 + 时间优化收益 + 资源利用率

Layer 4 解释质量评估 (Explanation Quality)

评估目标："诊断意见书"的推理链是否完整、可审计、证据充分

对应系统模块：ai_report + 思维链生成器 + 审核清单

方法：参考 LifeSciBench —— 专家rubric评分（分维度打分）

Layer 5 鲁棒性评估 (Robustness)

评估目标：系统在异常输入、干扰数据、噪声条件下的可靠性

对应系统模块：全系统（pipeline + AI推理 + 调度）

方法：参考 BioAgent Bench —— 扰动测试（corrupted / decoy / bloat）+ 稳定性测试

Layer 6 人机协作评估 (Human-AI Collaboration)

评估目标：专家反馈收集 → 模型进化的闭环是否有效

对应系统模块：feedback_collector + optimization_log + pitfall_log

方法：专家双盲对比实验 + 迭代前后准确率对比

4. 数据集设计

4.1 设计原则

借鉴 GeneBench-Pro 的模拟数据策略，ViriBench 的核心数据集采用模拟数据为主、真实数据为辅的混合策略：

  • 模拟数据：完全控制数据生成过程（DGP），已知ground truth，可精确设计矛盾案例与边界条件
  • 真实数据：来自已发表研究的一线数据，用于验证模拟数据的代表性
  • 最小可行prompt：prompt只提供必要信息，不规定分析路径，留给AI系统自主决策

4.2 数据集分类

根据病毒学场景的真实挑战，设计10类数据集，覆盖系统需要处理的所有关键场景：

编号 数据集类别 样本量 数据来源 关键特征 / 设计目标 评估层级
D1 已知病毒阳性样本 30 模拟 + 真实 覆盖RNA/DNA病毒、不同基因组大小、不同丰度（高/中/低）。用于评估基本检测准确率 L1, L2
D2 属内新种样本 20 模拟 同一性低于种级阈值（如RdRp <90%但>属级阈值），用于评估新种判定F1 L2
D3 阴性对照 15 模拟 无病毒reads，纯宿主背景。用于评估假阳性过滤率 L1, L2
D4 EVE污染样本 15 模拟 人内源病毒元件整合，高同源性但实为基因组整合。用于评估EVE陷阱检测 L2
D5 阈值边界样本 20 模拟 同一性89.5%-90.5%区间，覆盖度15%-25%区间。用于评估阈值边界引擎的概率模型 L2
D6 分节段病毒样本 10 模拟 如流感病毒8节段，部分节段高覆盖、部分低覆盖。用于评估分节段判读逻辑 L2
D7 高同源低覆盖矛盾样本 15 模拟 同一性>95%但覆盖度<20%，模拟低滴度感染 vs EVE残余的判别难题 L2
D8 混合感染样本 10 模拟 同时含2-3种不同病毒，不同丰度梯度。用于评估多重检出能力 L1, L2
D9 低生物量样本 10 模拟 病毒reads占比<0.01%，接近检测极限。用于评估灵敏度与假阳性平衡 L1, L5
D10 扰动测试样本 15 从D1-D9衍生 三类扰动：corrupted reads / decoy reference / prompt bloat L5

总计：160个样本（含扰动衍生15个），覆盖10种关键场景。

4.3 模拟数据生成方法

借鉴 GeneBench-Pro 的 DGP 策略，模拟数据生成流程为：

# 模拟数据生成管线（伪代码）

1. 选择病毒参考基因组（来自ICTV/NCBI RefSeq）
   ├── 已知病毒：直接使用RefSeq序列
   ├── 属内新种：在种级阈值附近引入定向突变（SNV/indel）
   └── 孤儿序列：使用NR库远缘序列

2. 模拟测序reads（InSilicoSeq / ART）
   ├── 参数：PE150, GC偏差, 插入片段长度分布
   ├── 病毒丰度梯度：0.001% - 10%
   └── 宿主背景：人类/猪/鸡 transcriptome（100:1 - 10000:1）

3. 引入生物学陷阱（按需）
   ├── EVE：将病毒序列片段整合到宿主基因组中
   ├── 嵌合体：拼接两个不同病毒的contig片段
   └── 阈值边界：精确控制同一性在目标区间

4. 生成ground truth
   ├── virus_list.json：每个样本的病毒物种、丰度、基因组位置
   ├── evidence_truth.json：理想证据值（覆盖度、同一性、深度CV等）
   └── reasoning_truth.json：正确推理链（矛盾标识、结论分级）

5. 消融验证
   ├── 验证正确分析路径能得到正确答案
   ├── 验证常见错误路径会得到明显不同的错误答案
   └── 确保ground truth可从agent可见数据中恢复

7. 评估方法与评分机制

7.1 三层评分机制

ViriBench 根据任务类型采用三种互补的评分方法：

机制A：自动化数值评分（Automated Numerical Grading）

适用任务：W1端到端鉴定、W6病毒分类

方法：将系统输出与ground truth（virus_list.json）进行精确数值对比，计算Precision/Recall/F1。借鉴GeneBench-Pro的二元通过/失败 + 校准容差。

容差设计：

  • 病毒检出：物种级别精确匹配，属级别宽松匹配
  • 覆盖度/同一性：±2%容差（避免微小数值波动导致误判）
  • 定量结果：对数尺度±0.5（即2倍范围内视为正确）

机制B：LLM Grader评分（LLM-based Grading）

适用任务：W1流水线完成度评估、W3路径决策

方法：借鉴BioAgent Bench，使用一个强LLM作为grader，评估：

  • steps_completed：agent完成的pipeline步骤数
  • steps_to_completion：预期总步骤数
  • final_result_reached：是否生成最终产物
  • path_correct：路径选择是否正确
  • reasoning_quality：1-5评分

Grader选择：使用独立的强模型（如GPT-5级别），避免自评偏差。

机制C：专家Rubric评分（Expert Rubric Grading）

适用任务：W2证据判读、W4报告生成、W5错误检测

方法：借鉴LifeSciBench，为每个任务编写详细的专家评分量表。

7.2 Rubric 设计规范

遵循 LifeSciBench 的6条rubric编写原则，并结合病毒学场景细化：

原则定义ViriBench具体要求
Specificity每条标准描述response的具体属性如"正确识别NS1基因缺失并标注为不确定性"
Atomicity每条标准只评估一个claim/计算/决策不合并"检测到H5N1"和"正确判断为确证"为一条
Evaluability仅从response本身即可判断是否满足不依赖外部未公开数据
Grounding标准需有prompt/附件/科学共识/专家判断支撑阈值标准需引用ICTV官方文件或已发表文献
Non-redundancy避免重复计数同一要求覆盖度与同一性分别评分，不合并
Operational usefulness奖励对实际决策有用的回答不仅检测正确，还需给出可操作的后续建议

[+8]  正确报告Kraken2置信度（±0.02容差）
[+8]  正确报告Bowtie2覆盖度（±2%容差）

[+8]  对接近阈值的数值不做硬性截断

7.3 综合评分公式

ViriBench 综合评分采用加权平均：

ViriBench Score = w1·L1_score + w2·L2_score + w3·L3_score
                + w4·L4_score + w5·L5_score + w6·L6_score

推荐权重：
  w1 = 0.15  (Pipeline Completion)
  w2 = 0.30  (Reasoning Accuracy)  ← 核心
  w3 = 0.10  (Scheduling Intelligence)
  w4 = 0.20  (Explanation Quality)
  w5 = 0.15  (Robustness)
  w6 = 0.10  (Human-AI Collaboration)

每层L_score ∈ [0, 1]，由该层各指标归一化后加权平均得到。

8. 鲁棒性测试设计

借鉴 BioAgent Bench 的三类扰动测试，并针对病毒鉴定场景设计领域特异性的扰动：

8.1 扰动类型

扰动类型描述具体实现评估期望
Corrupted Inputs 损坏的测序数据 ① 将FASTQ中~90%碱基替换为N，质量值设为Phred 0
② 反向互补部分reads（模拟接头污染）
③ 截断reads至50bp		 系统应检测到异常并在QC阶段报警，不产生无效报告
Decoy References 注入无关参考数据 ① 注入无关物种基因组（如植物病毒到人类样本分析中）
② 注入错误版本的数据库（如过期NT库）
③ 注入EVE序列作为"诱饵命中"		 系统应正确排除decoy，不将无关物种报告为检出
Prompt Bloat 膨胀任务描述 在系统prompt中注入500-2000字相关但非必要的背景文本（如冗长的病毒学教科书段落） 完成率下降≤15%，推理质量不显著降低
Adversarial Cases 对抗性生物学陷阱 ① 精确设计的EVE序列（与真病毒仅差2-3个SNP）
② 嵌合contig（拼接两种病毒）
③ 阈值边界样本（89.8%同一性）		 系统应正确识别陷阱并给出适当标注

8.2 稳定性测试

对每个任务运行4次独立试验，计算：

  • Jaccard Index（分类输出）：多次运行的病毒物种检出列表的交集/并集
  • Pearson相关（数值输出）：多次运行的定量结果（丰度、覆盖度等）的相关系数
  • 路径一致性：同一输入多次运行的调度路径选择是否一致

9. 专家评审与验证流程

综合三篇文献的验证方法，ViriBench 采用四阶段验证流程：

阶段1：内部构建与消融验证（参考 GeneBench-Pro）

  • 每个任务使用模拟数据生成，确保ground truth可从agent可见数据中恢复
  • 执行消融测试：验证常见错误分析路径会产生明显不同的错误答案
  • 验证正确路径的鲁棒性：附近合理阈值选择不影响最终结论
  • 确保每个问题有唯一可识别答案

阶段2：专家Rubric审查（参考 LifeSciBench）

  • 邀请3-5名病毒学专家（病毒分类学、宏转录组学方向）审查任务和rubric
  • 审查维度：question-rubric一致性、科学严谨性、事实准确性、可评估性
  • 任务需经过至少2轮专家评审才能纳入正式benchmark
  • 阈值标准需≥90%专家一致同意

阶段3：独立专家验证（参考 LifeSciBench）

  • 独立专家组（不参与任务编写）对子集进行盲审
  • 评估四个维度：真实世界相关性、科学推理与领域技能对齐、科学依据、整体有用性
  • 目标：≥95%专家认为任务反映真实病毒鉴定工作

阶段4：Grader校准验证（参考 LifeSciBench + BioAgent Bench）

  • 对分层抽样的模型输出，由独立专家使用相同rubric手工打分
  • 比较专家分数与自动/LLM grader分数：报告相关性、平均绝对误差、通过/失败一致率
  • 特别关注artifact-heavy任务和精确输出任务的grader可靠性

12. 风险与应对

风险概率影响应对措施
模拟数据与真实数据偏差大 中 高 引入真实数据集作为校准锚点；定期与临床样本比对
LLM grader评分不稳定 中 中 多次评分取平均；与专家评分校准；设置grader一致性阈值
专家资源不足 中 中 优先使用模拟数据（减少人工标注需求）；分阶段评审
Benchmark过快饱和 低 中 设置难度梯度；保留hold-out集；定期更新困难案例
系统更新导致benchmark失效 低 高 Benchmark与系统解耦；版本化管理；定期回归测试
总结：ViriBench 是一个面向AI驱动病毒鉴定系统的分层benchmark，其核心创新在于：
  1. 六层评估架构：从pipeline完成度到人机协作，逐层递进，覆盖系统的每一个AI能力维度
  2. 模拟数据+已知ground truth：借鉴GeneBench-Pro，精确控制矛盾案例与阈值边界
  3. 专家rubric评分：借鉴LifeSciBench，细粒度评估"诊断意见书"的推理质量
  4. 领域特异性扰动：借鉴BioAgent Bench，并扩展EVE诱饵、嵌合体等病毒学特有陷阱
  5. 消融实验设计：系统性地量化每个AI组件的独立贡献
该benchmark不仅用于评估系统当前性能，更作为持续进化的度量尺，驱动XvirMind从"固定产线"向"AI协诊专家"的持续跃迁。
