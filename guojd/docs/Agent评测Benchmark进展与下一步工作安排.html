2. ViriBench 目标架构（规划）

L1 流水线完成度

工具/参数/IO 是否忠实于 Snakefile；规划路线是否与标准路径一致。

L2 AI 推理准确性

矛盾检测、阈值边界、EVE、新种判定、分类准确率；需要模拟数据 + ground truth。

L3 调度智能

紧急/标准/深度路径选择；时间与资源收益。

L4 解释质量

诊断意见书证据是否可追溯；专家 rubric。

L5 鲁棒性

corrupted / decoy / prompt bloat；稳定性（多次试验 Jaccard / Pearson）。

L6 人机协作

专家反馈后是否真正改进；迭代前后准确率提升。

7. 百分制评分方案（VAS-1.0）

详细公式、指标定义、JSON schema、跨 Agent 接口与反作弊清单见： ViriBench VAS 百分制评分规范。 本节是进展报告中的执行摘要。

引入 VAS（ViriBench Agent Score）：每层先打到 0–100，再按权重合成总分 100。这样每次优化可以看「总分涨了多少、涨在哪一层」；其他同类 Agent 只要实现 AUT 适配接口，也可在同一 suite 下对比。

7.1 权重与总分

层权重（分）层内核心指标（详见规范）主要借鉴
L1 执行完成度18VER, SCR, PFR, FAR, TPFScienceAgentBench VER；BioAgent Bench completion
L2 推理准确性28L2-O 数值区间；L2-D 检出 F1；L2-T 矛盾/EVE/边界GeneBench-Pro；研究方案验证指标
L3 调度智能10RAC, CR, CA, TC, EHR, TBR路径正确率；紧急通道 ≤25min
L4 解释质量18GRD, HAL, COT, RUB, CHKLifeSciBench rubric；证据锚定
L5 鲁棒性16COR, DEC, PBR, STB, pass^kBioAgent Bench 扰动；τ-Bench pass^k
L6 人机协作10FIX, DLT, ACC, EFF反馈修复率；迭代提升
VAS = 0.18·L1 + 0.28·L2 + 0.10·L3 + 0.18·L4 + 0.16·L5 + 0.10·L6

两种模式：

  • development：只对已激活层重归一化（当前适用），必须披露 coverage。
  • official：六层全评，未实现层记 0；用于发版与跨 Agent 对比。

L1L4L5VAS_dev（L1+L4+L5）等级

预期：确定性 runner + 确定性报告上线并重跑后，L1.TPF 与 L4.GRD 应明显上升；修好 decoy 识别后 L5 可再抬一截。具体升降以同协议重跑为准。

7.3 版本对比与跨 Agent

  • 版本对比：固定 suite_id + protocol_version + task_set_hash，输出六层雷达 + VAS 折线；主分提升 ≥2 或目标层 ≥5 且无显著回退，视为有效优化。
  • 跨 Agent：统一 AUT 产物（plan / artifacts / report / tool_events / costs）；主排序 VAS，并列看 pass^k → Cost → WallTime。
  • 副指标（不进百分制）：API Cost、Tokens、WallTime、ToolCalls——防止靠重试刷分。

7.4 与「只报 hit/miss」的关系

逐条 criterion 仍然保留（可审计、可定位 G001 这类问题）。VAS 是其上的聚合层：rubric 负责「哪条错了」，VAS 负责「整系统多少分、比上周高了吗、比别的 Agent 强吗」。

8. 下一步工作安排
