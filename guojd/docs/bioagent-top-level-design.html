01 / 战略定位与壁垒做可私有化的领域系统，而不是再做一个通用 Agent

团队已明确：前端交互和通用 Agent 框架容易被开源工具替代，也可以直接接到 DeepSeek Harness 一类现成编排器上。真正难以复制、且必须留在疾控内网的，是垂直领域的本地数据库、审核过的专业知识，以及在算力受限的量化模型上把生信任务做稳的能力。

本地化产业化易迭代更新本地数据库

可替换层 · 不作为产品壁垒

交互界面与通用 Harness

Open WebUI、Claude Agent SDK、DeepSeek Harness 以及任何 OpenAI 兼容会话前端，只负责把用户意图送进本系统的动作契约。领域规则、权限、方案编译、计算插件和报告模板不得写入某一家 SDK。更换编排器不应要求重写 workflow 或知识库。

领域内核 · 建设重心

本地库 · 知识 · 规则 · 研判

NT/NR/Kraken/CheckV 等参考库以离线版本包交付；ICTV、技能、工具说明和文献以可审核知识快照交付；鉴定规则与矛盾检测独立于模型。本地小模型只在这些资产上做窄任务，并用专家修订做后续微调。

产业化含义：交付物不是一份绑定特定云模型和特定聊天框架的演示，而是可在疾控环境安装的资产包——计算插件、参考库、知识快照、规则包、本地模型和业务数据库。其中任何一层更新，都应能单独发版、单独回滚，而不重训整个系统、不改写历史报告。

02 / 建设目标与价值让每个结论都有可检查的依据

系统面向宏转录组分析人员、项目负责人和病毒学专家，从 FASTQ 或规范的中间分析产物出发，组织已知病毒识别与未知病毒候选发现，交付结构化分析结果、证据支持的研判意见和运行审计记录。未知候选意味着当前证据尚不能完成归属，需要进一步分析或专家复核。

稳定完成分析

用户选择目标，系统补齐依赖、校验输入并执行已验证流程。计算状态独立于对话模型，断线后可重新核对任务进展。

缩短获得信息的等待

智能模式先交付阶段快报，再继续已确认分析。优先级与资源约束由调度规则管理，完成时限以实测估算为依据。

积累可复用的专业能力

将分类依据、分析方法、工具约束、本地库版本和专家修订转化为审核过的知识与数据库资产。更换前端或 Harness 不影响核心流程和证据标准。

建设优先级：本地数据库与知识发布 > 计算插件版本化 > 多证据研判 > 本地小模型微调 > 交互和 Harness 适配。后两项只为维持闭环，不作为差异化功能继续加厚。

目标能力：受控自动分析、候选级证据整合、可引用的知识解释和专家审核闭环。报告用于科研鉴定与研判；分类归属、证据强弱和专家审核分别呈现。

已实现指源码中存在对应能力，验证范围见工程附录。待建设纳入实施路线。条件接入须服务可用且专项验证通过。

本文描述目标架构。当前具备 Workflow 1–6 的编译与执行接入、数据集及方案版本、远端运行管理和确定性数值报告等基础；完整项目管理、知识库、专家审核和本地模型迁移仍需建设。本次完成源码核对，未执行 Cyclone 全流程验收。

03 / 四层总体架构四层业务流程，共享知识与证据支撑

四层按业务职责划分，并且必须允许「编排与计算分离」。浏览器与业务后端只做交互和权限；编排节点只做方案编译、知识检索和模型调用；计算节点只通过注册过的插件执行 Snakemake。知识服务和本地参考库是共享资产，分别支撑研判与比对，都不进入 Agent 进程内部。Claude Agent SDK 或 DeepSeek Harness 属于编排节点上的可替换运行时，不是第四层业务的一部分。

层级 输入与核心职责 输出及进入下一层的条件
数据输入层 管理员维护项目与成员；分析人员建立会话，选择远端文件或上传数据，记录样本、测序批次、宿主背景及对照关系。校验类型、配对、样本一致性、路径和文件指纹。 可追溯的数据集版本。文件上传结束且预检通过后才允许编译方案；中间产物须满足目录中定义的完整文件契约。
方案交互层 用户选择分析目标和模式；模型解释能力并提出结构化修改建议；编译器依据工具目录、技能预设及约束补齐依赖。 含数据集版本、步骤、参数、参考库及资源预算的方案版本。用户看到改动与代价并确认后，后端才发起执行。
计算运行层 持久化队列决定顺序；worker 校验输入和版本，runner 组织各 phase，Snakemake 按依赖和资源执行具体任务。 带运行身份与来源的初筛结果、完整分析产物、指标和日志。计算失败保留已完成内容，报告明确其覆盖范围。
数据交付层 证据服务读取产物并核算，规则服务识别冲突，知识服务返回依据，主 Agent 生成受约束的说明，专家审核与补证。 阶段快报、完整分析／研判报告、审核记录、运行审计包。核验失败不发布受影响的正式结论；不隐藏其他已验证产物。

04 / 一次分析如何完成先确认目标，再让计算和证据推动下一步

  1. 归入项目，建立分析会话项目是权限、样本组织和调度管理的单位；会话承载一次分析意图，可包含多版数据集、方案和执行记录。重复测序批次与生物学样本分别建模，合并关系由用户确认。
  2. 冻结本次输入远端文件选择与上传共用数据预检入口。原始文件保持只读，记录逻辑路径和经准入检查的真实目标；输入变化产生新数据集版本，旧版本保留。
  3. 展示可执行方案并确认模型将“质控松一点”等请求映射为已发布的参数预设，展示具体变化；未定义的参数请求必须澄清。去除 rRNA、宿主序列去除和宿主识别分别建模，只有接入并验证的能力可供选择。
  4. 排队与执行执行前再次验证输入指纹、方案版本与工具参考库。近期重型分析一次准入一个任务；内部阶段可在资源额度内并行。队列规则决定顺序，模型不分配线程或跳过用户目标。
  5. 分批交付可验证的结果智能模式产生 5% 初筛快报后继续完整目标。资源不足时保留快报并等待资源；输入、工具等错误则转入明确的阻塞或失败状态。快报不会把正在进行的完整任务标为完成。
  6. 形成研判，进入专家复核对每个候选整理数值证据、知识引用、冲突和缺失项。专家可认可、要求补证或提出修订；修改报告形成新版本，补做计算形成新的确认动作。
模式 / 入口 目标行为 边界与适用条件
智能 成对 reads 可用时执行 5% 初筛，交付快报，再完成用户选择的目标。 已知病毒信号只影响提示与补证建议。仅有 contig 等中间输入时，确认页面明确改用标准流程。
紧急 完成预定快检范围即可交付；首期沿用现有 5% 抽样、质控、去 rRNA 与 Kraken2 初筛链路。 计划确认前明确“抽样快检”，不承诺全量检测；不具备成对 reads 时不接受此模式。阴性表述限定为本次范围内未检出。
标准 按用户目标编译依赖闭包，完成相应质控、组装、识别、定量或注释。 只执行已注册的能力；合法中间输入可以省去已完成的上游步骤。
专项深度分析 从候选及证据缺口出发，追加已接入的分类、系统发育等任务，并复用经验证的上游产物。 条件接入 不设空泛的第四条路由；展示所需输入、服务状态、成本和交付物后单独确认。

智能模式“先快报、后完整”是本次提出的目标变更。当前代码在满足初筛门槛时可提前结束整个 pipeline；当前不适用初筛的输入会归一化为标准模式。相关修改列入阶段 1。

05 / 数据库与知识库计算读取参考序列，研判读取有出处的知识

生信参考库回答“序列与哪些参考对象匹配”；知识库回答“在何种条件下，这些结果支持何种解释”。业务数据库记录谁提交、确认和审核了什么，运行存储保存能够复算的实际产物。四类存储通过稳定标识与版本关联。

最小知识底座如何落地

首期部署一个知识模块，使用版本化资料包、SQLite 关系表和全文索引。节点与有出处的关系构成最小知识图谱，全文检索提供原文定位；四类资产共享检索入口，并保留各自的治理规则。知识模块在应用侧运行，大型参考索引与 FASTQ 留在 Cyclone。

检索先依据任务、类群和版本筛选，再按别名、标志基因及关键词查找相关关系与片段。面向中文问题预处理中文词项，英文专业名和 taxon ID 保持可精确查找。只有在固定评测集上证明能改善召回与引用质量，才增加向量检索；检索分数只用于排序。

发布流程：资料导入 → 来源与许可登记 → 结构化整理 → 专家审核 → 冻结知识版本 → 回归验证 → 发布。分析或研判记录所用快照；新知识只影响新版本研判，历史报告保留原有引用。

参考库采用不可变版本目录。大型索引在发布时计算文件清单和校验信息，执行时核对登记清单及完整性状态，避免每次扫描整个 NT/NR。版本发生变化时阻止未经确认的续跑；已有历史库版本未知时明确标记，不能把目录名推断为完整的版本证明。

知识库如何构建：五条资产线，一条发布流水线

知识建设与业务 CRUD 并行，不排到「页面都做完」之后。先保证断网可检索、每条事实有出处、发布可回滚，再谈向量检索或自动抽取。模型抽取的内容只进待审核区，不能直接成为线上事实。

工具库与知识图谱如何进入报告

报告不是模型通读全部结果后写的作文。固定数据流为：计算插件写出 typed artifact → 解析器生成候选级计算证据（身份、完整性、覆盖、同一性等）→ 规则服务按类群命中矛盾/缺失 → 知识服务按候选检索适用规则和文献段落 → 主 Agent 只解释这份证据包 → 程序校验数值和引用 ID → 模板渲染。知识图谱提供「该用哪条规则、哪段原文」；工具库提供「这个数是哪个工具、哪版库、怎样算出来的」。缺任何一侧，都只能出数值报告，不能出研判结论。

易迭代更新：知识包、规则包、参考库、计算插件、本地模型五类资产各自编号。现场更新是「导入新包 → 校验 → 回归 → 切换默认快照」。正在运行的任务和已发布报告继续使用旧快照。失败则保留上一版本，不出现半更新状态。

06 / 编排层与本地模型让模型处理有限的问题，让系统承担稳定的责任

本地小模型按“意图识别、修改建议、知识问答、证据说明”分别评测和启用。应用将任务整理为短上下文：当前目标、允许动作、选定技能、标准化证据和检索片段；模型返回结构化结果，宿主服务校验后再进入业务流程。原始 FASTQ、大型日志和完整历史对话无需整体进入模型上下文。

组件 / 机制 负责的事情 实现与使用决定
业务规则 权限、输入有效性、参数范围、方案确认、队列优先级、资源准入及恢复条件。 确定性代码和配置，先于执行强制检查。自然语言说明与规则结果关联。
生物学判读规则 分类条件适用性、指标矛盾、缺失证据、阈值附近提示及专家复核触发条件。 有来源、版本和适用范围的规则包。保留实际阈值及观测差异；边界样本追加不确定性说明。
Snakemake rule 描述命令、输入输出文件、依赖、线程与资源额度。 由工程维护的 workflow 执行定义。通过固定适配器接入，模型不能生成并执行任意 rule。
Skill / 技能 提供完成某类任务的方法、可选预设、解释模板和审核要点。 确定性选择适用技能，再将少量内容交给模型；技能中的执行参数引用工具 schema，验证示例随版本发布。
主 Agent 咨询、澄清、生成方案修改提议、结合规则结果和引用解释候选证据。 保留一个对话与研判协调入口。模型供应方可替换，不直接拥有方案执行、业务库写入或计算节点 shell 权限。
多证据融合服务 标准化证据、识别矛盾、组织待解释事实并校验生成结果。 首期采用确定性服务＋主 Agent。一次研判可按候选分批调用同一模型，无需为每个候选创建自主 subagent。
专项 subagent 完成边界清晰、需要独立工具与专业上下文的专项任务。 条件接入 优先判断固定工具是否足够；只有多步决策确有收益、独立结果可验收时使用。任务限制工具、预算、超时和写入范围。
MCP 桥接 连接外部知识服务或独立专项服务，统一发现与调用能力。 由 BioAgent 宿主适配器控制调用及结果校验；本地函数直接调用，Cyclone 保留 SSH worker。MCP 是通信接口，其服务是否包含 Agent 由服务实现决定。协议依据
Harness / provider 会话传输与结构化生成。把短上下文送给 Claude Agent SDK、DeepSeek Harness 或本地 OpenAI 兼容服务。 可替换适配器。领域规则、编译、执行和知识检索不放进某一家 SDK。更换编排器不得要求重写 workflow 或知识包。

主 Agent 足够完成融合研判

关键计算、规则命中和来源定位已经由服务完成。主 Agent 的任务是解释一份有边界的证据包，输出支持项、反对项、缺失项和建议。额外拆分 Agent 会增加上下文交接与结果协调，首期没有足够理由承担这部分复杂度。

专项服务满足条件后再接入

ICTV 条目查询通过知识检索完成；需要独立分类算法或系统发育分析时，先注册为专项工具。若确实需要在多步专业分析间迭代决策，再采用 subagent。Workflow 6 已有注释能力，新增注释 Agent 必须有清晰的增量价值。

Harness 可替换，领域逻辑不进会话框架

编排层只通过 provider 接口调用模型：输入 task_kind、schema、有限上下文；输出结构化动作或研判草稿。Claude Agent SDK、DeepSeek Harness、本地 OpenAI 兼容服务（vLLM / llama.cpp 等）都是适配器。检索、规则、引用校验、工具调度和 Snakemake 启动由宿主执行，不要求本地模型自主多轮调用 MCP。

从 MiniMax-M3 迁移到疾控可落地的量化模型

先建设模型无关的动作、引用和研判契约，再让 MiniMax-M3 使用同样接口建立基线；本地量化模型只做影子评测，不产生业务动作。按能力切换：意图与追问 → 受控参数建议 → 引用式问答 → 候选证据说明。未达门槛的能力保持表单或人工路径。

私有化难点不在「再找一个更大的云模型」，而在算力受限条件下把四类窄任务做稳。记录量化方式、模型哈希和推理参数；用冻结任务集和专家修订计算结构化输出通过率、合法动作率、引用正确率、遗漏冲突率和幻觉率。专家审核过的「证据包 → 合格说明 / 不合格修订」形成微调语料，定期离线训练后以新模型包发布。训练不读取原始 FASTQ，也不把未审核对话直接当数据。

默认 local_only。模型不可用时保留表单规划、确定性执行和数值报告；没有管理员授权与用户确认，不得回退到云端。

07 / 证据研判与交付把计算事实、知识依据和专家判断连接起来

研判服务按候选收集证据，并保留样本与批次身份。数值证据需说明定义、单位、分母和来源，例如同一性针对核酸还是蛋白，覆盖率针对查询片段还是参考基因组。缺少深度 CV、系统发育支持度或对照结果时记录“未提供”，不以其他指标代替。

多证据融合的六个步骤

  1. 标准化：解析器将 workflow 产物变成候选级证据记录，区分核酸／蛋白同一性、比对覆盖／测序覆盖及 reads／read pairs 等不同口径。
  2. 检查：确定性规则识别高同源低覆盖、指标不一致、样本错配、重复或相关证据以及关键证据缺失。同一 reads 派生的结果归入来源组，避免简单叠加权重。
  3. 检索：根据候选类群、标志基因及异常模式获取适用规则与文献。返回空结果、来源冲突和不可用状态时保留不确定性。
  4. 说明：主 Agent 仅对证据包和引用内容生成结构化研判草稿；规则产生的冲突和缺失项必须保留，不允许凭语言推测新增样本事实。
  5. 核验：程序验证数值、单位、来源定位、引用身份及规则适用范围；文献是否充分支持解释仍需专家复核。正文由模板渲染，模型只提供经校验的结构化内容。
  6. 审核：专家检查对照、混合感染、分节段、EVE、污染、组装质量和类群标准的适用性。修订追加审核记录；报告和知识分别产生新版本。
分别呈现的维度 报告中的含义 避免的混淆
分类归属 已支持到的分类层级、候选归属或当前无法分类，并记录所采用的分类版本。 无法分类不直接等于新病毒或新物种；新分类单元的正式认可遵循 ICTV 程序。
证据支持程度 按审核规则给出“充分支持”“有限支持”“证据不足”或“现有证据不支持当前候选归属”。 规则未建立时使用“证据不足”；不把模型自信程度、Kraken 初筛门槛或检索分数写成概率。
冲突与缺失 独立列出相互矛盾的证据、阈值附近情况、未测项目和缺失对照。 可与任一支持程度并存；不得为得到单一标签而消去冲突。
审核状态 草稿、待审核、已审核、需补证或已被新版本替代。 计算完成与专家审核完成分别计数；审核认可也保留原有适用范围与限制。

示意案例：某候选蛋白局部同一性为 91%，查询覆盖率为 18%。系统首先核对比较对象、覆盖分母和数据来源，再标记“高同源低覆盖”，检索该类群的判定条件并提出补证要求。仅凭这两个数值，不给出确定分类，也不能认定 EVE 或污染。

CheckV 可提供完整度和宿主污染相关信息，其结果需结合工具适用范围解释；它不能独立承担全部嵌合、EVE 或污染排查。参见 CheckV 原始研究。上述数值为设计示意，非本系统实测。

C · 资源调度、断线与断点续跑
  • 队列：默认一个重型分析运行，单一调度者按管理员项目优先级、项目内紧急级和入队时间选择下一任务。等待老化规则避免长期饥饿；不抢占正在执行的 Snakemake job。
  • 资源：线程和内存额度来自经过验证的预设及历史估算；在阶段边界重新准入。共享慢盘上的并行以磁盘吞吐为约束，初筛和大型参考库查询同样计入资源预算。
  • SSH 断线：显示缓存状态与连接更新时间，远端任务继续存在。重连后联合 state、tmux、PID 和 boot ID 核对，不据此直接判为分析失败。
  • 指纹暂不可验：返回可重试状态并保留数据集原状态；确认 link 或 target 变化才标记 stale，要求新建版本。
  • 任务中断：已运行进程消失或机器重启时保留 interrupted 及产物。用户申请恢复后，验证输入、方案、软件、参考库和已完成输出，建立新 attempt；只有完整且一致的产物可以复用。
  • 版本变化：新建方案和 run，显式引用可复用产物。Snakemake 的增量执行能力需要系统级版本与身份约束配合，不能仅凭输出文件存在判断可续跑。
  • 阶段快报：作为独立、不可变的报告版本保存。完整分析未完成或失败时保持其原范围和标识；资源不足不会静默删去用户选择的目标。

原稿中的设想 本版决定与原因

所有专业能力都拆成 Agent 分类查询采用检索，固定算法采用工具，多证据说明使用主 Agent；subagent 只服务于确有收益且可独立验收的专项任务。

本版未进行模型或病毒识别性能测试，不提供准确率、节省时间或可并行任务数的实测承诺。后续上线门槛由冻结评测集、业务风险和计算资源共同确定。

09 / 分阶段建设路线先把事实和知识管好，再逐步替换模型

各阶段以验收门槛推进，不预设未经评估的完成日期。建设分成三条可并行的轨：领域资产轨（本地库、知识、规则）、业务闭环轨（项目、上传、队列、报告）、模型替换轨（provider、量化模型、微调数据）。知识与本地库不再等待全部页面完成才开工。交互和 Harness 适配只维持闭环，不单独立项做「更强的通用 Agent」。

2 · 知识与本地库 与阶段 1 并行：四类知识资产、参考库发布目录、统一检索、审核发布和引用校验。 每条可信引用可回到具体版本和原文位置；空检索和冲突有明确处理。
3 · 研判与审核 候选级证据、规则融合、引用式研判及专家修订。 冲突和缺失不被隐藏；报告数值可复核，审核可追溯。
4 · 本地模型与微调 provider 解耦（含 DeepSeek Harness 适配）、量化模型影子评测、按能力切换；用审核修订积累微调包。 本地默认可用；模型失败不影响确定性流程；迁移前后可同条件比较。
5 · 条件接入专项能力 通过验证的 ICTV 等专项工具或 Agent。 服务健康、输入输出、证据格式、权限及失败处理均有专项验收。

具体代码落点、最小接口变化、验收案例、迁移和回退方式、知识库建设步骤见 分阶段实施清单 v1.1。现状评价见 建设情况总结。本地模型的硬件、量化方案与推理后端在阶段 4 依据现场算力选定；阶段 0 先记录可用资源和参考库版本。
