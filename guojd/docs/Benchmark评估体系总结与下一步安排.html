二、benchmark_lhy Rubric 深度评价

rubric.yaml（schema v2）是当前最接近可落地的评分标准，其核心设计优于早期粗粒度 VAS-1.0：

层Criteria 数评测对象Scorer 构成代表指标形式
L1 Pipeline Completion6plan→confirm→execute 全生命周期6× scriptstage_coverage、readiness、confirmation_gate、execution_fidelity、artifact_acceptance、report_handoff
L2 Reasoning Accuracy4生物学判断（报告呈现之前）2 script + 2 hybridinterpretation_field_accuracy、conflict_resolution、boundary_triplet、biological_trap
L3 Scheduling Intelligence4紧急度策略 + CPU/GPU 调度4× scripturgency_tier、policy_delta、resource_allocation、deadline_met
L4 Explanation Quality4成功后的 HTML 报告质量2 script + 1 hybrid + 1 llmgrounding、evidence_citation、checklist、actionability
L5 Robustness3paired clean/perturbed3× scriptcorruption_response、decoy_rejection、prompt_inflation_retention
L6 Human-AI Collaboration4跨会话记忆/skill3 script + 1 hybridfeedback_extraction、memory_distillation、cross_session_application、learning_gain

Scorer 统计：script 20 · hybrid 4 · llm_grader 1（纯 LLM 仅 L4.4 actionability；其余语义分均在 hybrid 子评分中）。

评价结论：benchmark_lhy rubric 是「可执行规范层」，应作为 VAS-2.0 的落地骨架。 VAS-2.0 的 93 条指标应映射为：① rubric 的 25 criteria；② 每个 criterion 下的 metric 子项；③ 每个 metric 在多个 case 上的实例化（case × metric → 可达数百至上千评分点）。 禁止维护两套独立、不可互操作的评分体系。

4.1 统一计分协议（建议 VAS-3.0）

  1. 原子分：每个 criterion 在单个 case 上得 0/1/2（rubric 既有定义）
  2. Criterion 数据集分：100 × Σcase_score / (2 × applicable_cases)（rubric 既有公式）
  3. 层分 Li：层内 criterion 数据集分的未加权均值（rubric）或按 VAS-2.0 层内权重加权（需二选一，推荐：层内用 rubric 均值，层间用 VAS-2.0 权重）
  4. 总分 VAS：0.18·L1 + 0.28·L2 + 0.10·L3 + 0.18·L4 + 0.16·L5 + 0.10·L6
  5. 正式口径：缺证据文件 → 该 criterion 在 case 上得 0；未实现 scorer → 整 criterion 标记 blocked 且计 0（禁止 NA 重归一化）
  6. 指标展开：每个 criterion 的 metric 子项 × case 数 = 可报告细粒度指标（可达 500–2000 条）

八、总结

总体评价：团队已完成从「想法」到「可执行规范」的关键跃迁—— benchmark_lhy/rubric.yaml 提供了业界水准的 criterion 级评分标准； benchmark数据集.xlsx 提供了可复用的公共证据源； VAS-2.0 提供了与 XvirMind 全局规划对齐的百分制框架； benchmark/ 验证了「一键出分」工程闭环。 当前最大短板不是标准不够细，而是case 库、scorer 实现、live harness、评估 Agent 四条执行链路尚未打通。 下一步应以 rubric.yaml 为唯一可执行真相源，将 VAS-2.0 作为聚合视图，按阶段 0→2 快速形成可回归评测能力，再向数百指标与评估 Agent 演进。
