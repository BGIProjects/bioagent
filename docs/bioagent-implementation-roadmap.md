## 1. 设计对齐与本轮决定

### 1.1 新旧版本实际变化

建设目标调整为可向疾控机构私有化交付的病毒鉴定与专家研判能力。交付范围包含可安装的服务、注册计算插件、本地参考库、审核知识、规则和本地模型，以及更新、兼容校验、备份与回滚机制。当前本机＋Cyclone 是开发实例，目标部署的节点、路径和服务地址应由配置确定。

| 方面       | 旧版基础                                       | 新版要求及本清单的落实                                                        |
| ---------- | ---------------------------------------------- | ----------------------------------------------------------------------------- |
| 产品定位   | 围绕当前开发环境完成科研分析与审核闭环         | 在独立疾控环境安装、断网运行和维护；新增 M3 私有化交付验收                    |
| 建设重点   | 业务、知识、模型按阶段推进                     | 本地参考库、审核知识、规则、插件和小模型窄任务优先；从 M0 启动三轨            |
| 可替换层   | 已规划模型 provider                            | 前端与 Harness 也可替换；业务权限、知识、规则、编译与报告模板独立于供应方 SDK |
| 编排与计算 | 已有 SSH worker 与 Cyclone 分离                | 形成可配置的部署边界与插件契约，保留现有计算能力，逐步解除机器和目录绑定      |
| 领域资产   | 已有知识图谱、技能、工具、文献及参考库版本设计 | 增加五条资产建设线、离线包、兼容组合和独立更新流程                            |
| 本地模型   | 四类任务分别评测，本地默认、不自动回云端       | 强化量化部署与现场资源评测；provider 和本地基线提前到 M0                      |
| 微调       | 没有明确训练建设路径                           | 审核修订形成数据包，离线训练、评测、量化复测后批准发布                        |
| 实施顺序   | 旧清单采用 0 → 1 → 2 → 3 → 4                   | 改为三条研发轨道与 M0–M3 共同验收节点，取消无必要的整阶段等待                 |

审核附言既说明产品方向，也补充了 HTML 尚未落实的执行要求。四种划分分别使用：四层业务流程是输入、方案、计算、交付；部署职责是交互与业务服务、宿主编排服务、计算服务；五条资产线是分类知识、方法技能、工具契约、文献、本地参考库；三条研发轨道是 A 业务闭环、B 领域资产、C 模型替换。逻辑职责可同机运行，也可拆开部署，无须为了层数增加进程。

### 1.2 以本轮确认为准的范围

- **三种模式近期均保留：**智能、标准、紧急。智能模式先出初筛快报，再完成已确认目标；附言只提标准／紧急不视为删除智能模式。
- **M0 先做资产到证据报告 demo：**复用可追溯计算结果，贯通本地资产、规则、检索、本地模型说明、引用校验和报告；不等待完整项目管理，不要求第一步重跑完整 FASTQ。
- **provider 先行，DeepSeek Harness 按需：**近期接通现有 MiniMax 路径和一种本地推理后端；新版阶段表中的“含 DeepSeek Harness 适配”不作为近期必交付项。
- **默认 local_only：**模型不可用时保留表单、确定性执行和数值报告。云端基线比较或回退仍须管理员允许与用户显式确认，不自动外发。
- **本地或 5090 先检查可用性：**推理与训练分别盘点资源。当前部署说明将 TaxonAgent／5090 标为不可用，本轮未重新探测；不将 5090 设为其他轨道的前置条件。
- **微调纳入建设：**审核数据整理 → 离线训练实验 → 评测 → 最终量化产物复测 → 批准发布。训练实验和上线是不同动作，不按日历自动替换模型。
- **用途仍为鉴定与专家研判：**疾控私有化明确客户和交付环境；新版正文仍保留科研表述，未据此增加临床诊断用途或相关验证承诺。

知识图谱继续保留：分类知识用有出处的实体和关系组织；方法进入技能库；执行能力进入工具契约；原文与摘录进入文献库；参考索引由计算工具读取。它们统一治理，但不使用同一种读取方式。Harness 和推理引擎都可以由 provider 适配，它们本身仍是不同类型的组件；DeepSeek Harness 具有工具、技能和调度等能力，将其限制在结构化生成边界内是本系统的选择，参见[官方说明](https://www.deepseek.com/harness/en/)。

**2026-09-12 本轮实施范围调整（用户确认）：**当前机器不部署小模型，使用显式授权的 MiniMax-M3 验证 provider 与报告链路；不等待专家，先建设约 16 KiB 的待审核资料与工程规则包。已完成真实初筛冻结、关键指标原始产物复算、SQLite 检索、引用校验、开发报告和断网降级验证。S0／A0／B0／C0 的工程完成项与 D0 未完成项分别记录；不把 MiniMax 草稿或模拟异常算作本地模型／生物学验收。详细命令、依赖缺失项和产物见 [实施记录](m0-implementation-record.md)。

### 1.7 Workflow 2 工程研判业务接入（第 22 轮）

### 1.9 业务、资产与 run 恢复快照（第 24 轮）

- [x] **一致性与内容身份：**DeploymentProfile schema v2 登记业务 SQLite、备份根、保留数量和 20 GiB 默认硬额度；SQLite 在线 backup、版本化 Agent assets、已登记 run 的 `state.json`／`reports/` 组成同一 staging snapshot，每个普通文件记录 size 与 SHA-256，manifest 自身另有摘要。
- [x] **恢复前检查：**验证 SQLite `quick_check`、九张核心业务表、十类项目／成员／chat／dataset／plan／execution／assessment／review 关联、持久化工程引用结构、run state JSON、逐档摘要、意外文件和总大小；任何不符均 fail closed。
- [x] **非覆盖恢复演练：**恢复只允许写入不存在的新目录，经第二次全量验证后才原子改名；不覆盖业务库、资产或远端 run。当前实例实际快照／staging restore 均为 16 files、1,228,177 bytes、2 projects、2 members、1 registered run、10 relationship checks。

当前业务库没有 assessment 或持久化工程引用，真实演练对应计数均为 0；自动测试另以合法引用、篡改、孤儿关系和既有目标覆盖验证正负路径。工具不自动按保留数量删除旧备份，也未在独立恢复主机验证鉴权、历史报告访问或定期排程，因此 A5 第三项仍不勾选。详见[第二十四轮复现记录](m3-24-recovery-snapshot-reproduction.md)。

### 1.10 更新前准入控制（第 25 轮）

- [x] **原子运维状态：**DeploymentProfile schema v3 登记共享 admission state；operator CLI 以 0600 临时档、fsync、SHA-256 与原子 rename 切换 `accepting`／`draining`，未知 schema、篡改、symlink、超限或不可读状态均 fail closed。
- [x] **两层执行阻断：**Backend 在建立 execution reservation 前查询 Agent 准入；Agent 对直接 run start 与 resume 再次检查，关闭竞态与绕过。drain 只阻止新计算准入，方案编译、状态、证据和报告读取继续可用。
- [x] **运维入口与可观察性：**`dev-services.sh drain|resume|status` 复用 profile 中同一状态文件，Agent health 及专用只读 endpoint 返回状态；维护原因和更新时间可追溯，缺省未配置保持既有接受行为。

本轮只完成 A5 第四项中“更新前停止新准入、业务服务不终止远端计算”的工程切片。尚无 B4／C3 合格包可做联合更新、兼容拒绝或回滚，未停止真实服务或干预 Cyclone scheduler／runner，因此 A5 第四项与 M3 仍不勾选。详见[第二十五轮复现记录](m3-25-admission-drain-reproduction.md)。

### 1.11 离线依赖 BOM 与介质 preflight（第 26 轮）

- [x] **源码依赖身份：**Agent Python 3.11 新增 48 个 direct／transitive exact pins；Backend 复用 `uv.lock` 的 356 个 package／2,358 个 artifact hash，Frontend 复用 npm lock v3 的 1,274 个 package integrity identity。preflight 对三档逐一计算 size／SHA-256，拒绝未 pin、缺 hash、未知字段、symlink 与越界路径。
- [x] **目标平台介质契约：**七类必需介质明确拆为 source、Agent wheelhouse、Backend uv cache、Frontend npm cache、Pyodide cache、系统 runtime 和计算 runtime；`media-manifest.json` 必须逐组件登记 platform、architecture、相对路径、size 与 SHA-256，缺件、多件、额外档、篡改和 symlink 均 fail closed。

### 2.4 保持的开发与运行约束

- 原始 FASTQ 不修改、不搬动；计算和生信测试产物仅写入 run root。上传测试使用专用测试 run 下的隔离目录，不污染真实 dataset。

- 停止本机服务不得终止远端分析；SSH 失联不等于任务失败。远端指纹暂不可验保持 dataset 原状态并返回 retryable 503，确认改变才标记 stale。

- 私有密钥不输出、不入库；配置模板只维护 tracked `.env.example`。参考库、文献和模型的离线分发按来源许可登记。
- 本地模型、知识快照、证据校验独立失效时分别报告状态。无显式云端授权就使用本地旧版本、模板或专家路径。

- [ ] MCP client 由宿主持有，查询与启动计算分别授权。远端超时先查实际状态，缺少幂等／状态查询的计算服务不开启自动重试；原有 SSH worker 不为统一形式而改为 MCP。
- [ ] 只有固定工具不足且多步专业决策确有评测收益时采用 subagent，限制工具、上下文、预算和写入范围；不修改主方案、原始输入或正式报告，不自行无限派生 Agent。
- [ ] 专项结果经过样本／候选、版本、来源和 schema 校验后进入证据图；UI 以“追加专项分析”展示，不增加空泛的第四种 deep 路由。

**产物／代码落点：**SpecialistTask、专项适配与验收集；复用 `taxonagent_adapter.py` 的边界及工具目录、宿主调用和候选展示。**验收：**不可用、版本变化、重复确认、超时但仍运行、证据缺失、错配和越权均处理正确。**回退：**关闭入口，核对在途任务，保留历史证据；基础分析和本地知识能力不受影响。

### 8.2 按变更选择检查

代码修改遵循仓库顺序：相关 Python／Vitest 测试 → Ruff → Prettier check → 涉及前端应用时最后只运行一次 build。`npm run check` 的大量既有类型错误不作为验收依据。

| 变更                   | 优先测试                                                                                        |
| ---------------------- | ----------------------------------------------------------------------------------------------- |
| 插件目录、参数和编译   | agent 的 test_deterministic_planner、test_workflow_adapters、test_deterministic_runtime         |
| 初筛、队列、恢复与 SSH | agent 的 test_adaptive_routing、test_analysis_runner、test_remote_worker、test_remote_client    |
| provider 与动作        | agent 的 test_conversation_contract、test_runtime、test_adapter，再运行冻结真实模型评测         |

Agent／后端测试按根 README 在对应目录与 conda 环境运行。真正执行生信的测试单独登记 run，不能写回原始 FASTQ；模型训练与推理评测按所选环境单独登记，不在常规单元测试中隐式启动。

### 8.3 上线观察与退出条件

- **执行：**重复启动、排队等待、资源原因、SSH 缓存状态时间、中断／恢复、插件或参考库校验失败。
- **领域资产：**检索不足、失效定位、拒绝引用、冲突保留和专家修订原因，按知识／规则／参考库版本区分。
- **模型：**按 task_kind 观察结构错误、成功率、延迟、幻觉／遗漏、内存与不可用；单独记录显式云端调用及授权范围。
- **发布：**来源不可复算、关键引用失效或候选错配时停止受影响结论发布，保留已验证计算产物；兼容或包校验失败时不切换默认版本。
- **恢复：**定期演练业务库、资产、运行与报告恢复，验证权限、历史引用、在途任务和模型包一致性；保留期限由项目要求配置。
